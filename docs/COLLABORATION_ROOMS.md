# Confectory Document Rooms · 저장과 확정

이 변경은 기존 독립 작업자·WorkContext·ChangeSet·Resolution 구현 위에 [추가 확정 설계](COLLABORATION_ROOMS_SPEC.md)를 통합한다. Human, AI, 에디터팩은 같은 Participant와 Room을 사용한다. 현재 Windows 호스트 안에서 공유 작업본을 사용하며, 원격 Human의 접속·인증·네트워크 전송은 아직 연결하지 않았다.

## 사용

- 작업자 탭의 **참여자 리스트**는 소유자, 현재 파일 Room, 세부 작업 위치, 상태, 공개 작업 설명과 읽지 않은 답변을 보여 준다. **위치 따라가기**로 해당 파일을 연다.
- AI 캐릭터에 있는 입력란으로 직접 말한다. **대화 로그**는 기록·설정 창이다. 별도의 DM 입력 창을 만들지 않는다. 공개 작업 설명은 소유자가 직접 작성하며, 개인 요청 본문을 자동 공개하지 않는다.
- **Full / Compact / Hidden**은 내 화면에만 적용한다. Hidden도 계속 작업한다. 표시를 바꾸는 것만으로 답변을 읽었다고 기록하지 않는다. 파란 점의 **새 답변 보기**, 말풍선 클릭, Turn 이동으로 실제 표시한 메시지를 확인한다.
- **프로젝트 채팅**과 문서의 **Room 채팅**에서 `@이름` 또는 `@참여자ID`로 AI를 부른다. 중복된 이름은 ID로 구분한다. 일반 대화는 모든 AI를 호출하지 않는다.
- 공개 호출은 독립된 새 제공자 대화와 공개 상태만 사용한다. 개인 로그, 요청, Yogi, 파일 편집 도구를 넘기지 않는다. 다른 소유자의 AI 호출은 공개 메시지로 기록하며, 그 소유자의 연결이 처리해야 한다. 원격 연결은 아직 제공하지 않는다.

## 문서와 에디터팩

C# 문서는 기본적으로 멤버 목록을 보여 준다. 함수·생성자·속성·필드·이벤트·타입을 선택해 해당 단위만 편집한다. 지원되는 선언은 접근, 한정자, 타입, 이름, 매개변수, 초기값을 별도 필드로 조절할 수 있다. 복합 필드·연산자·복잡한 선언은 선언 텍스트로 편집한다. **구조 / 전체 문서**로 원문 편집을 선택한다.

완성한 단위를 작업본에 반영할 때 구문을 검사하고 하나의 변경으로 삽입한다. 일반 텍스트 입력은 즉시 Working Copy를 갱신한다. 저장·체크포인트에서 완성된 문서만 의미 단위로 정리하고, 같은 Room에서 해당 파일에 Depend/ModifyIntent를 가진 활성 작업자에게 이벤트를 남긴다. 각 키 입력으로 모델을 호출하지 않는다. 외부 Room의 작업자는 확정된 ChangeSet을 통해 변경을 받는다.

**초안 저장**은 기기 상태 폴더에 작업본을 보존한다. 프로젝트 파일, 확정 Revision, 충돌 상태를 바꾸지 않는다. 저장된 초안은 문서를 닫았다가 열어도 복원된다. **확정** 또는 **검토한 변경 확정**은 기존 검토·원본 해시 재확인·파일 교체 경로를 이용한다. 아직 검토 중인 후보는 외부 작업자에게 확정으로 전파하지 않는다.

AI는 관측한 Shared Working Copy에서 자신의 변경만 만든다. 사용자와 다른 요소를 수정했다면 디스크에는 AI 변경만 확정하고, 사용자의 미확정 변경은 Shared Working Copy에 유지한다. 기본 정책은 기존의 명시적 검토다. 소유자가 **겹치지 않는 검증된 단위 자동 확정**을 켜면, 완성된 기존 파일의 의미 단위만으로 구성된 묶음을 자동 확정할 수 있다. 새 파일/등록/이미지 묶음과 빌드·실행·창 조작이 포함되면 기존 검토를 유지한다. 구문·XML 계약 검사를 컴파일 성공으로 기록하지 않는다.

겹치면 묶음 전체와 후속 작업을 `handoff`/`deferred`로 남기고 파일을 바꾸지 않는다. **인계 초안**에서 변경을 확인하고, 겹친 단위를 선택해 내 작업본으로 받거나 버릴 수 있다. 받는 행위도 프로젝트 확정은 아니다. Room 퇴장은 저장·확정과 독립되어 있다.

여러 파일은 기존 검토 배치의 사전 검사·동일 dispatcher 내 적용·실패 시 역순 복구를 사용한다. 실제 빌드와 테스트는 모든 파일 반영 이후의 명시적 단계다. 전체 코드의 타입·호출 관계를 완전히 검증하는 언어 서버나 분산 트랜잭션은 아니다.

## 계약

| 모델 | 역할 |
| --- | --- |
| DocumentRoom | 파일 정체성, 현재 참가자, 작업본 버전, 작성자별 초안 |
| RoomDraft | 관측한 기준, 의미 변경, 작성자, 요청, 저장·인계 상태 |
| ParticipantPresence | 프로젝트 연결 여부, Room, Scope, 읽기·편집 상태 |
| ParticipantView | 관찰자별 표시 방식과 실제 읽은 메시지 ID |
| CollaborationMessage | 공개/Room/개인 경계, 중요도, 명시적 mention, 대화 계보 |
| ContextHandoff | 목표·완료·진행·제약과 초안 ID; 명시적 제안·수락 |
| SemanticNotice | 완성된 체크포인트의 변경 대상; Room별 최신 이벤트로 병합 |

C#은 Roslyn 구문 트리의 멤버와 Signature/Body/Suffix를 이용한다. 같은 한 줄에 있는 서로 다른 함수도 분리한다. 같은 멤버의 선언과 본문은 직접 겹침과 의존 영향을 구분한다. 추가·삭제·이름/타입 식별자 변경·모호한 구조는 기존 보수적 텍스트 비교로 돌아가며, 주석·공백을 버리지 않는다. XML은 기존 요소 단위 비교를 재사용한다.

`packengine_collaboration`은 기존 state/reference/respond/discuss에 leave, handoff, accept_handoff를 더한다. YIELD는 미확정 초안을 남기며, TAKEOVER는 수락된 인계가 있어야 한다. 수락된 인계가 일반 AI 제어권을 넘기지는 않는다. AI 대화는 Thread ID와 깊이를 기록하고 10회에 도달하면 사용자 응답 필요 상태로 멈춘다. 공개 답변의 mention을 자동으로 계속 실행하지 않는다.

소유권 검사는 UI와 모델 양쪽에서 수행한다. 다른 소유자의 AI는 공개 presence·채팅·Resolution에 참여하고 내 화면에서 숨길 수 있지만, 직접 작업, 취소, 이동 명령, Yogi, 개인 기록, 자동 확정 정책은 소유자 경계를 따른다. 재시작은 과거의 presence를 실제 연결로 표시하지 않고 미완료 AI 초안을 인계 상태로 복원한다. 모델 추론을 재전송하지 않는다.

## 검증 범위

Windows WPF/net48 교차 빌드, 작업자/Room/공개 문맥/권한 및 실제 에디터팩 변경 테스트, 고정 게임 SDK를 사용하는 전체 캠페인으로 확인한다. 실제 Windows 마우스·키보드·말풍선 배치, 인증된 모델의 공개/개인 동시 응답, 원격 참가자 동기화는 이 Linux 실행 환경에서 확인하지 않았다. Android 호스트에 새 Windows 참여자·문서 UI를 이식하지 않았으며, HP·라운드 자동 해결도 앞선 구현 단계와 마찬가지로 후속 범위다.
