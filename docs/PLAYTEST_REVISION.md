# 플레이 조작과 대화 개편

## 영역 수집·제작 및 구매 제한·비조종 골렘 방전 (2026-09-30)

- 모든 골렘의 작업 목록과 땅 우클릭에 '이 주변 아이템 줍기'를 추가한다. 지정 타일의 맨해튼 거리 6칸 안에서 접근 가능한 물건을 찾아 1칸 거리까지 이동해 수집하고 복귀한다. 수용 가능한 품목이 없으면 기준 지점에서 대기하며, 가방 공간이나 새 물건이 생기면 재개한다.
- Logistics DLL의 collect_area는 IContinuousAction과 ISelfNavigatingAction으로 구현한다. 기준 지점·현재 대상·검색 시각은 골렘의 저장 데이터에 남는다. UI의 hold 모드는 취소까지 유지한다. exact 모드는 한 차례 수집 후 복귀·완료하여 다음 예약으로 진행할 수 있다. 기존 E/긴 E의 즉시 수집은 유지한다.
- 제작 항목의 활성 여부와 수량 상한은 제작 DLL의 Check를 사용한다. 재료 부족·잠금·공간 부족 항목은 지우지 않고 클릭만 막는다. 호버는 결과물 설명·필요 재료·실패 이유를 표시하며 Shift 예약에서는 예상 재고를 사용한다.
- 구매 상한은 공유 PurchaseRules로 UI와 Commerce DLL이 함께 판정한다. 최대 1개면 N개 선택지를 만들지 않고, 0개면 설명을 볼 수 있는 비활성 상품으로 남긴다. 이미 배운 서적·진행상 잠긴 서적·금화·적재 한도를 반영한다. 서적 2권 이상이나 이미 배운 책의 재구매는 실제 금화 차감 전에도 거부한다.
- CanOperate는 현재 조종 여부와 재생 여부를 모두 본다. 마나 0에서 일반 이동·예약·작업·수호·수집·반격도 정지하며, 넉백·피해·사망 처리는 계속된다. 멈춘 작업의 경로·진행도·재료 점유·예약을 보존한다. 비조종 골렘에 마나 젤리를 사용해도 기존 명령을 취소하지 않는다. 방전된 골렘의 걷기/작업 반복 모션을 멈추고 골렘 관리 호버에 충전 대기를 표시한다.
- 기존 이동당 마나 소모와 작업 완료 비용에 더해 공격 1회·영역 수집 1회에 마나 0.5를 사용한다. 빈 영역이나 가방이 찬 상태의 대기에는 마나를 소모하지 않는다.

## 주문·전투·버블 사용성 수정

- 주문 버블에 마우스를 올리면 전체 주문명, 각 물건의 아이콘과 보유/필요 수량, 금화·평판 보상을 표시한다. 보유량은 납품에 쓰이는 현재 골렘과 상점 안 창고만 합산하고 다른 작업의 점유량을 뺀다. 수락한 주문은 재료가 부족하면 납품을 비활성화하지만 내용은 계속 볼 수 있다.
- Ctrl+수량 액션은 1개, Alt+수량 액션은 가능한 전체를 즉시 실행한다. 마우스를 누를 때의 보조키를 유지하며, 건네기/가져오기 아이템·제작품·구매품 버블에서도 수량 선택을 바로 생략한다. 시설 슬롯과 드래그 전달도 같은 수량 처리를 쓴다.
- 몬스터 소재는 바닥에 등장한 뒤 처치한 골렘이 자동 습득한다. 가방 초과분은 바닥에 남고 E로 주울 수 있다. 직접 버린 물건·철거 부산물·사망한 골렘의 소재는 자동 습득하지 않는다.
- 전투 골렘의 작업 목록과 땅 우클릭에 `지역 수호`와 `이 지점까지 공격`을 추가한다. 수호는 지정 지점 주변 6칸 안의 적을 처리하고 복귀하며 새 지시로 해제한다. 공격 이동은 주변 적을 처리한 후 목적지 이동을 이어간다. 하나의 액션으로 녹화·예약·저장하며 잠긴 보스를 먼저 공격하지 않는다. 시간 지정 경호도 종료 뒤 다음 예약으로 진행한다.
- 골렘 사망 시 장착·휴대 장비와 강화는 소실된다. 일반 가방 물건은 원래 위치에 stack 단위로 떨어지고, 장착 핵과 가방의 핵은 공방으로 즉시 회수한다. 이미 바닥에 있던 물건은 변경하지 않는다.
- 장비·메모리·건설·조립·주문·안내·전체 일지·일시정지 창은 같은 버튼을 다시 누르면 닫힌다. 메뉴 차단막에서도 열린 창의 원래 버튼만 닫기 입력을 받는다.
- 압축 후 실행 가능한 행동이 완전히 하나라면 대상 좌클릭으로 실행한다. 우클릭은 한 개라도 버블을 표시한다. 다른 선택지가 있거나 실행 불가이면 메뉴를 유지한다.
- 말줄임표가 생긴 이름은 마우스를 올리면 전체를 펼친다. 상세 미리보기가 없는 행동은 이름만 작게 표시하고, 제작·주문 등은 기존 상세 미리보기에서도 전체 이름을 보여준다.

`ISelfNavigatingAction`은 장기 액션 DLL이 이동 경로를 직접 유지·갱신할 때 선택적으로 구현한다. 엔진은 해당 경로를 매 틱 지우지 않으며 기존 공격 추격 동작은 유지한다. 신규 `tactics` 능력은 기존 저장의 전투 골렘에도 객체 정의 기본값으로 적용한다.

## 예약 이동과 건설 접근 수정

- 나무·시설의 그림 범위 안에서 점유 칸의 투명한 틈을 클릭해도 해당 물체를 선택한다. 겹친 다른 물체의 불투명 픽셀을 우선하며, 골렘의 이미지 영역 판정은 유지한다.
- 이미 저장된 이동 예약이 나무나 시설의 막힌 칸을 가리키면, 도달 가능한 외곽의 인접 칸에서 이동을 완료한다. 이동을 수확으로 바꾸지는 않는다. 이동 불가 지형 자체는 허용하지 않는다.
- `IActionApproach`는 행동 DLL이 작업 대상의 사각형 범위와 최소·최대 접근 거리를 제공하는 선택적 계약이다. 건설은 시설 전체 범위 바깥에 정지하며, 제작 골렘이 이미 부지 안에 있으면 먼저 걸어나온다.
- 건설 미리보기와 사전 검사는 작업자 자신만 제외한다. 다른 골렘이나 시설은 계속 설치를 막고, 완공 직전에 다시 검사하므로 충돌 시 재료를 소비하지 않는다.
- 건설·장애물 이동의 외곽 접근 지점은 한 번의 경로 탐색으로 고른다. 대기 중인 예약의 실패 이유를 골렘 상태에 표시한다.
- `--approach` 검증은 연속 벌목, 장애물 이동 예약, 모서리 접근, 자기 부지에서 나가기, 건설 예약·예상 재고·저장 복원, 다른 골렘 진입과 막힌 출구에서의 재료 보존을 확인한다. Windows smoke에는 나무 밑동 선택 검증을 추가했다.

- 수량: 숫자·슬라이더 아래에 `1개 / −10 / −5 / −1 / 중간 / +1 / +5 / +10 / Max`를 한 줄로 표시한다. 확인은 바로 아래 넓은 버튼 하나다. Ctrl=1개, Alt=전체, Shift=예약을 유지한다.
- 대화: 전체 클라이언트를 서서히 어둡게 하고 일러스트와 하단 대사를 표시한다. 글자는 Unicode 텍스트 요소 단위로 출력한다. 첫 클릭/Enter는 현재 문장을 완성하며, 다음 입력이 다음 대사로 이동한다. 말할 때만 입 패치를 재생한다.
- 일상 공격: UI에서 `Mode=until_down`으로 명령한다. 이동·추격·공격이 하나의 예약/녹화 단계이며 목표가 쓰러지면 다음 단계로 간다. 전투 직접 공격은 `Mode=once`다. 새 일반 명령과 수동 이동은 현재 명령과 예약을 취소한다.
- 단축키: 상단 숫자 1~0. Ctrl+숫자는 현재 골렘 조종 액션을 등록한다. 액션 버블 또는 사용 가능한 가방 아이템을 단축키로 드래그해 등록할 수 있다. 슬롯 우클릭에서 마지막으로 실행한 행동도 등록하거나 슬롯을 비울 수 있다. 수량·대상 등 전체 요청을 저장한다.
- 클릭: 마지막으로 실제 그린 프레임, 표시 오프셋, 회전, 알파 마스크를 사용한다. 앞에 그린 물체부터 검사하며 이동·충돌 타일은 그대로다. 호버와 드래그 대상도 같은 판정을 쓴다.
- 용량: 작은/아름다운 진열대는 합계 4개. 훈증기는 연료 10, 약초 3, 액체 3, 출력 합계 5개다. 출력 공간이 부족하면 진행도·재료·열 소비를 멈추고 공간이 생기면 이어간다. 저장된 초과 재고는 삭제하지 않는다.
- 시설: 진열대 위에 실제 판매 아이템을 표시한다. 훈증기는 재고 아이콘/개수와 진행 막대, 실제 생산 중에만 불·연기 애니메이션을 표시한다.
- 바닥: 모든 드롭 경로는 각 아이템의 stack 단위로 나눠 떨어뜨린다. 소유자 자동 습득 규칙과 수량 보존을 유지한다.
- 장비: 가방과 별도 소유권을 가진 `Equipment` 슬롯에 1개를 옮긴다. 가방에서 슬롯으로 드래그하거나 클릭으로 장착·해제할 수 있다. 교체 장비는 비워진 가방 칸으로 돌아간다. 가방이 꽉 차 해제할 수 없으면 상태를 바꾸지 않는다. 관리 창의 골렘 아래에서도 장착 아이콘이 보인다.
- 녹화/반복: 좌하단 작업 목록에서 제외하고 메모리 창에서 관리한다. R/T 키는 유지한다.

## 팩 계약

`Object capacity`는 종류/묶음 수가 아닌 전체 개수 상한이다(0은 기존 slots/stack 규칙). `InputSlots outputCapacity`도 전체 출력 개수 상한이다. 각 `Slot capacity`는 해당 입력칸의 개수 상한이다.

`Item equipmentSlot="weapon|shield|사용자 정의 슬롯"`으로 장비를 선언한다. 모드 슬롯과 알 수 없는 장비 데이터도 저장한다. 기존 `Data.weapon/shield` + 가방 장비는 로드 시 한 번만 실제 슬롯으로 옮긴다.

`IContinuousAction`은 DLL이 선택적으로 구현한다. `Continue`의 Started는 진행 중, Success는 한 단계의 완료를 뜻한다. 엔진이 추격·예약·녹화·저장·취소를 관리한다. 오류와 길 막힘에도 중복 완료하지 않는다.

`HotbarAction`은 아이콘, 이름, `ActionRequest`를 저장한다. ActorId가 비면 현재 조종 대상을 사용한다. 없는 팩의 액션도 저장에서 삭제하지 않는다.

대화는 `Portrait` 접두사(기본 `dialogue.enrin`), `Mood`, `Side=left|right`, 선택적 `ListenerPortrait`를 가진다. Sprite 이름은 `dialogue.enrin.neutral` 같은 형식이며 idle/talk 애니메이션을 제공한다. talk의 `compositeOver="idle"`, `overlayX/Y`는 기준 그림의 로컬 픽셀 위치다. 시트의 입 영역만 얹으므로 몸과 머리는 흔들리지 않는다.

## 이미지 설치와 검증

새 일러스트는 별도 `Golemancer_Dialogue_Content_Art_v1.zip`의 `Content/Packs/92.DialogueArt`에 들어 있다. 기존 Content에 한 번 합치면 된다. 팩이 없는 동안에는 기존 초상화를 사용한다. 이미지 원본과 gitignore는 코드 푸시에서 변경하지 않는다.

헤드리스 검증은 장비·용량·분할 드롭·저장·연속 공격 예약/재생·텍스트 출력 및 전체 캠페인을 확인한다. `Verify.bat`의 Windows smoke에는 한 줄 수량 배치, 핫키, 장착칸, 메모리 창, 표시 오프셋을 가진 실제 이미지 클릭, 전체 화면 대화 검사를 포함했다. Linux에서는 Windows UI smoke를 실행하지 못하므로 실제 창 배치와 애니메이션 감각은 Windows에서 확인해야 한다.
