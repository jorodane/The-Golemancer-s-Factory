# 플레이 조작과 대화 개편

- 수량: 숫자·슬라이더 아래에 `1개 / −10 / −5 / −1 / 중간 / +1 / +5 / +10 / Max`를 한 줄로 표시한다. 확인은 바로 아래 넓은 버튼 하나다. Ctrl=1개, Alt=전체, Shift=예약을 유지한다.
- 대화: 전체 클라이언트를 서서히 어둡게 하고 일러스트와 하단 대사를 표시한다. 글자는 Unicode 텍스트 요소 단위로 출력한다. 첫 클릭/Enter는 현재 문장을 완성하며, 다음 입력이 다음 대사로 이동한다. 말할 때만 입 패치를 재생한다.
- 일상 공격: UI에서 `Mode=until_down`으로 명령한다. 이동·추격·공격이 하나의 예약/녹화 단계이며 목표가 쓰러지면 다음 단계로 간다. 전투 직접 공격은 `Mode=once`다. 새 일반 명령과 수동 이동은 현재 명령과 예약을 취소한다.
- 단축키: 상단 숫자 1~0. Ctrl+숫자는 현재 골렘 조종 액션을 등록한다. 액션 버블 또는 사용 가능한 가방 아이템을 단축키로 드래그해 등록할 수 있다. 슬롯 우클릭에서 마지막으로 실행한 행동도 등록하거나 슬롯을 비울 수 있다. 수량·대상 등 전체 요청을 저장한다.
- 클릭: 마지막으로 실제 그린 프레임, 표시 오프셋, 회전, 알파 마스크를 사용한다. 앞에 그린 물체부터 검사하며 이동·충돌 타일은 그대로다. 호버와 드래그 대상도 같은 판정을 쓴다.
- 용량: 작은/아름다운 진열대는 합계 4개. 훈증기는 연료 10, 약초 3, 액체 3, 출력 합계 5개다. 출력 공간이 부족하면 진행도·재료·열 소비를 멈추고 공간이 생기면 이어간다. 저장된 초과 재고는 삭제하지 않는다.
- 시설: 진열대 위에 실제 판매 아이템을 표시한다. 훈증기는 재고 아이콘/개수와 진행 막대, 실제 생산 중에만 불·연기 애니메이션을 표시한다.
- 바닥: 모든 드롭 경로는 각 아이템의 stack 단위로 나눠 떨어뜨린다. 소유자 자동 습득 규칙과 수량 보존을 유지한다.
- 장비: 가방과 별도 소유권을 가진 `Equipment` 슬롯에 1개를 옮긴다. 가방에서 슬롯으로 드래그하거나 클릭으로 장착·해제할 수 있다. 교체 장비는 비워진 가방 칸으로 돌아간다. 가방이 꽉 차 해제할 수 없으면 상태를 바꾸지 않는다. 관리 창의 골렘 아래에서도 장착 아이콘이 보인다.
- 녹화/반복: 좌하단 작업 목록에서 제외하고 메모리 창에서 관리한다. R/T 키는 유지한다.

## 팩 계약

`Object capacity`는 종류/묶음 수가 아닌 전체 개수 상한이다(0은 기존 slots/stack 규칙). `InputSlots outputCapacity`도 전체 출력 개수 상한이다. 각 `Slot capacity`는 해당 입력칸의 개수 상한이다.

`Item equipmentSlot="weapon|shield|사용자 정의 슬롯"`으로 장비를 선언한다. 모드 슬롯과 알 수 없는 장비 데이터도 저장한다. 기존 `Data.weapon/shield` + 가방 장비는 로드 시 한 번만 실제 슬롯으로 옮긴다.

`IContinuousAction`은 DLL이 선택적으로 구현한다. `Continue`의 Started는 진행 중, Success는 한 단계의 완료를 뜻한다. 엔진이 추격·예약·녹화·저장·취소를 관리한다. 오류와 길 막힘에도 중복 완료하지 않는다.

`HotbarAction`은 아이콘, 이름, `ActionRequest`를 저장한다. ActorId가 비면 현재 조종 대상을 사용한다. 없는 팩의 액션도 저장에서 삭제하지 않는다.

대화는 `Portrait` 접두사(기본 `dialogue.enrin`), `Mood`, `Side=left|right`, 선택적 `ListenerPortrait`를 가진다. Sprite 이름은 `dialogue.enrin.neutral` 같은 형식이며 idle/talk 애니메이션을 제공한다. talk의 `compositeOver="idle"`, `overlayX/Y`는 기준 그림의 로컬 픽셀 위치다. 시트의 입 영역만 얹으므로 몸과 머리는 흔들리지 않는다.

## 이미지 설치와 검증

새 일러스트는 별도 `Golemancer_Dialogue_Content_Art_v1.zip`의 `Content/Packs/92.DialogueArt`에 들어 있다. 기존 Content에 한 번 합치면 된다. 팩이 없는 동안에는 기존 초상화를 사용한다. 이미지 원본과 gitignore는 코드 푸시에서 변경하지 않는다.

헤드리스 검증은 장비·용량·분할 드롭·저장·연속 공격 예약/재생·텍스트 출력 및 전체 캠페인을 확인한다. `Verify.bat`의 Windows smoke에는 한 줄 수량 배치, 핫키, 장착칸, 메모리 창, 표시 오프셋을 가진 실제 이미지 클릭, 전체 화면 대화 검사를 포함했다. Linux에서는 Windows UI smoke를 실행하지 못하므로 실제 창 배치와 애니메이션 감각은 Windows에서 확인해야 한다.
