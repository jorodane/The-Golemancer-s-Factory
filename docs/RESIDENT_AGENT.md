# Codex 입주 실험 — 객체팩 문맥과 ‘이거’ 모드

이 문서는 **에디터 안의 별도 Codex 채팅**을 설명한다. ChatGPT의 기존 대화에서 직접 에디터를 다루려면 **[ChatGPT MCP 연결](CHATGPT_BRIDGE.md)**을 사용한다. 그 방식에서는 대화 본문을 복사하지 않는다. **게임팩 대화 방식 선택**에서 **로컬 Codex 대화**를 고르면 이 방식을 사용한다. 선택과 대화 원본은 게임팩 안에 저장한다. [여러 기기에서 이어가기](PROJECT_CONVERSATIONS.md)를 참고한다.

Project Studio 안에서 지속되는 Codex 대화와 실제 편집 도구를 연결한 첫 환경이다. Windows WPF 에디터가 공식 Codex CLI의 `app-server`를 실행한다. ChatGPT 계정으로 로그인하고 계정에서 제공하는 모델을 선택한다. API 키로 자동 전환하지 않는다. 이용 한도와 추가 사용량 설정은 해당 Codex/ChatGPT 계정을 따른다.

로컬 방식을 선택한 프로젝트를 열면 저장한 기기별 접근 설정에 따라 Codex 연결과 로그인 상태를 자동 확인하고, 마지막으로 선택한 에디터 대화를 복원한다. 질문을 보내기 전에는 모델 요청을 시작하지 않는다. 프로젝트 명세가 선언한 명령이나 게임 DLL을 자동 실행하지 않는다. 웹 Work 대화·메모리·Library를 자동 이관하지 않으며, 웹 문맥은 아래의 링크·공유 문맥 등록으로 연결한다.

## 처음 시작하기

1. 저장소를 Pull한 뒤 루트 **`StartEditor.exe`**를 실행하고 첫 대화 설정에서 **로컬 Codex 대화**를 선택한다. 이후에는 게임팩의 선택을 기억한다.
2. Node.js/npm이 없으면 공식 설치 페이지가 열린다. LTS를 설치한 뒤 시작 창의 **다시 확인**, 에디터에서는 **Codex 설치 확인·다시 연결**을 누른다. 시작 프로그램이 필요한 `@openai/codex@0.159.2`를 사용자 폴더에 설치하고 실행 확인을 마친 뒤 에디터를 연다. 이 준비 과정에서는 로그인이나 모델 호출을 하지 않는다.
3. 에디터가 Codex에 자동 연결한다. **ChatGPT 로그인 필요**라면 한 번 **ChatGPT 로그인**을 눌러 공식 페이지에서 완료한다. 다음 실행에는 CLI가 보관한 로그인을 확인한다. 자동 연결을 껐거나 연결이 실패했으면 **Codex 연결**로 다시 시도할 수 있다.
4. 모델을 선택하고 일반 대화를 보낸다. 여기까지는 포인팅 첨부와 팩 수정 권한이 없다.
5. 객체를 가리킬 때 오른쪽의 모드를 바꾼 뒤 탐색기·관계·문서 탭에서 대상을 지정한다. 오른쪽의 대상 칩을 확인하거나 `×`로 제거할 수 있다.
6. 실제 수정을 맡길 요청에 **지정한 팩 수정·빌드**를 켜고 보낸다. 전체 검증이나 게임 실행도 맡기려면 **프로젝트 실행·검증**을 함께 켠다. 체크박스와 대상은 요청 전송 시점에 고정된다.

수정 실험 예시: **이거 · 단일 객체** → 탐색기에서 `widget:golemancer.costButton` 지정 → **지정한 팩 수정·빌드** → “이 버튼의 fontSize를 13에서 15로 바꾸고 해당 팩을 검증해줘.” 에이전트가 실제로 수행한 조회·변경·빌드만 기록된다. **변경** 탭에서 미리보기와 결과를 확인하고 필요하면 **이 변경 되돌리기**를 사용한다. 이 실험으로 게임 원본을 미리 바꿔 놓지는 않았다.

CLI 경로는 보통 비워 둔다. PATH, 통합 시작 프로그램의 사용자 설치 폴더, npm 사용자 전역 설치 폴더에서 네이티브 실행 파일을 찾는다. 직접 지정할 때는 `codex.exe`를 선택한다. npm의 `codex.cmd`는 사용할 수 없다. 프로젝트 빌드에는 .NET 10 SDK가 필요하며 `PACKENGINE_DOTNET`으로 다른 경로를 지정할 수 있다.

설치 중 실패하거나 취소하면 이전 설치 폴더를 유지한다. 두 창이 같은 위치에 동시에 설치하지 않도록 잠그며, 새로운 패키지는 임시 위치에서 네이티브 실행 파일과 버전을 확인한 뒤 사용 위치로 옮긴다. **실행 기록**에서 실패 원인을 확인하고 다시 시도할 수 있다. Node.js는 사용자가 공식 설치 프로그램에서 설치하며, 시작 프로그램은 시스템 관리자 권한을 요구하거나 계정·대화 기록을 바꾸지 않는다. 기존 두 bat 파일은 호환용으로 이 시작 프로그램을 연다.

## 프로젝트·대화 접근 설정

대화 상단이나 오른쪽의 **대화 목록·접근 설정**을 누르면 **대화·접근** 탭이 열린다. 계정 조회 결과의 이메일·플랜을 표시하며, 이 상태는 웹 기록에 대한 열람 권한과 구분한다.

| 설정 | 동작 |
|---|---|
| 시작할 때 Codex 자동 연결 | 기본 켜짐. 프로젝트를 열 때 연결·계정 확인·저장된 대화 표시. 모델 요청 없음 |
| Codex 연결 허용 | 끄면 이 에디터의 Codex 프로세스 연결을 차단 |
| 이 프로젝트에서 Codex 사용 | 직접 연 프로젝트별 허용·차단. 목록에서 프로젝트 선택 후 **이 프로젝트 열기**로 전환 |
| 대화 기록 열기·이어가기 허용 | 끄면 해당 프로젝트의 목록·본문 조회와 기존 대화 재개를 차단하고 요청마다 새 대화 사용 |
| 선택한 대화 접근 허용 | 선택한 기록의 본문 조회·재개 차단. 제목은 접근 설정을 바꿀 수 있도록 목록에 남음 |

설정은 사용자 폴더의 `PackEngine/assistant-settings.json`에 저장한다. 프로젝트 명세가 이 설정을 바꾸거나 다른 프로젝트 접근을 자동 승인할 수 없다. 에디터의 접근 제어이며 운영체제 권한이나 OpenAI 계정의 서버 권한을 변경하는 기능은 아니다.

**게임팩의 로컬 대화**는 게임팩에 보관한 기록을 먼저 나열하고, 공식 `thread/list`로 현재 PC의 이전 프로젝트 전용 기록도 조회한다. **이 PC**가 붙은 이전 기록은 열면 게임팩에 원본을 보관한다. 다른 클라이언트·프로젝트 기록은 제외한다. 30개씩 목록을 불러오며 **더 보기**로 계속 조회한다. 대화를 클릭하면 `thread/read`로 소속·접근 상태를 확인하고 `thread/turns/list`로 최근 10턴을 표시한다. **이전 메시지**로 더 읽을 수 있다. 모델의 다음 응답은 선택한 동일 ID를 `thread/resume`하여 이어간다. 기록 조회만으로 모델 요청을 만들지는 않는다. 다른 창에서 진행 중인 대화는 전환을 거부한다.

이 목록에는 게임팩과 함께 옮긴 기록과 현재 PC의 이전 에디터 기록이 있다. 로그인한 이메일에 연결된 웹 채팅 목록이나 계정별 원격 접근 제어로 해석하면 안 된다. 프로젝트 상태 파일에 남은 이전 요청들을 섞어 보여주지 않고, 선택한 공식 Codex 대화 기록으로 화면을 복원한다. 로컬 기록이 삭제됐거나 읽기에 실패하면 오류를 표시하며 다른 대화를 임의로 재개하지 않는다.

## 웹 ChatGPT와 문맥 연결

현재 사용하는 로컬 Codex app-server 연결에서는 웹 ChatGPT 프로젝트·채팅 목록의 자동 조회·동기화를 제공하지 않는다. 공식 app-server의 목록은 저장된 Codex 스레드이며, 구독 로그인 자체가 웹 Work의 기록·메모리 접근을 부여하는 것은 아니다. 웹 대화를 다음 방법으로 연결한다.

1. **대화·접근 → 수동 참고 메모 → 등록**에서 이름, `https://chatgpt.com/` 프로젝트·대화 링크, 공유할 텍스트를 넣는다. 링크는 브라우저에서 열기 위한 것으로 에디터가 본문을 가져오지 않는다. 본문 없는 링크는 문맥 공유 대상에서 제외한다.
2. **이 프로젝트의 Codex에 이 문맥 공유**를 켠 항목만 다음 요청에 사용한다. 기본은 비공유. 본문은 항목당 12,000자, 공유 항목은 프로젝트당 32개까지다.
3. Codex에는 먼저 제목·문맥 ID만 전달하고, 필요할 때 `packengine_read`로 지정된 `chat:` 경로의 일부를 읽게 한다. 본문·허용 목록을 전송 시점에 고정하고 실제 읽기를 따로 기록한다. 프로젝트 파일 수정 권한이 되지는 않는다.
4. **웹에서 열기**로 등록한 원문에 접근한다. 반대 방향으로는 대화 상단의 **대화 복사**로 현재 불러온 메시지를 복사해서 웹에 붙여 넣을 수 있다. 전체 내역이 필요하면 **이전 메시지**로 먼저 불러온다.

등록된 텍스트는 사용자가 제공한 문맥이며 자동 동기화된 원본이 아니다. 공유 해제·등록 해제는 다음 요청부터 적용한다. 이미 읽은 내용은 기존 대화 문맥에 남을 수 있으므로 이를 분리하려면 **새 대화**를 시작한다. 화면·마우스 스트리밍이나 브라우저 쿠키를 사용하지 않는다.

## 포인팅과 전송 시점

| 모드 | 사용자 입력 | 전송하는 내용 |
|---|---|---|
| 일반 대화 | 채팅 | 프롬프트, 열린 문서의 경로·버전·초안 여부. 문서 본문과 포인터 정보는 붙이지 않음 |
| 이거 · 단일 객체 | 탐색기 또는 관계도에서 한 객체 클릭 | 객체 ID, 소속 팩, 파일·XML 위치, 해당 정의 조각, 문서 버전 |
| 이거 · 범위 | 관계도에서 드래그, 탐색기에서 여러 객체 클릭 | 선택 집합의 객체 ID와 각 정의 조각 |
| 이거 · 범위 | 문서 탭에서 텍스트 선택 | 선택한 줄의 시작·끝, 내용, 문서 버전 |

마우스 이동이나 호버를 스트리밍하지 않는다. 보내기/Ctrl+Enter에서 프롬프트와 의미 입력 스냅샷을 함께 만든다. 응답 중 다음 포인팅 모드나 권한을 바꾸더라도 진행 중인 요청은 바뀌지 않는다. 첫 버전은 작업 중 문서 편집과 새 객체 선택을 잠근다. 새 프롬프트는 작성할 수 있고 작업이 끝난 뒤 보낼 수 있다.

텍스트 범위는 문자 단위가 아닌 줄 단위다. 범위를 고른 뒤 문서 내용이 달라지면 다시 선택하도록 요청한다. 객체 포인팅은 전송 순간의 정의를 읽는다. ID가 없어지거나 정의 위치를 찾을 수 없으면 다른 객체로 조용히 바꾸지 않는다. 한 요청은 최대 64개 대상, 본문 기본 예산 8,000자이며 큰 항목은 일부만 포함하고 누락을 표시한다.

상속 부모·연결 대상·구현 파일을 처음부터 전부 전송하지 않는다. Codex가 실제 작업에 필요한 정의와 한 단계 관계를 조회하고, 필요할 때만 구현 소스의 일부를 읽는다. 사용자에게 열린 문서, 처음 전달한 조각, 이후 제공자가 요청한 읽기, 실제 실행한 작업을 별도로 기록한다. XML 선언과 DLL의 실제 실행 상태를 같은 것으로 취급하지 않는다.

## 제공하는 실제 도구

| 도구 | 범위 |
|---|---|
| `packengine_editor` | 에디터팩 조회·부분 수정·빌드·동적 적용. 게임팩 권한과 별도이며 [에디터팩 명세](EDITOR_PACKS.md)를 따른다 |
| `packengine_find` | 프로젝트가 선언한 객체·문서 메타데이터 검색, 최대 30개 |
| `packengine_inspect` | 한 정의 조각, 한 단계 관계, 또는 저장된 상속 계약·출처 |
| `packengine_read` | 등록 파일 또는 허용한 `chat:` 문맥에서 최대 160줄/12,000자 읽기 |
| `packengine_patch` | 허용된 팩 안에서 유일하게 일치하는 문자열을 바꾼 미리보기 생성 |
| `packengine_apply` | 이번 요청이 만든 미리보기 적용. 변경 기록과 되돌리기 보존 |
| `packengine_build` | 허용된 팩의 선언된 소스 빌드 또는 XML 계약 검증 |
| `packengine_project` | 별도 허용한 프로젝트의 검증·smoke·게임 실행 |

포인팅 대상을 수정 범위로 승인하면 **그 객체가 속한 팩의 편집 가능한 파일**이 범위가 된다. 객체 하나나 선택한 줄만 수정 가능한 것은 아니다. 여러 팩 작업은 그 팩들을 함께 지정한다. 제공받은 읽기 전용 팩, 프로젝트 설정, SDK 계약은 이 도구로 수정할 수 없다. 기본은 읽기 전용이며, 조회 자체는 지정한 팩 밖의 선언된 관계로 확장할 수 있다.

패치는 모델이 실제로 받은 문서 해시와 현재 버전을 비교한다. 외부 수정이나 사용자의 미저장 버퍼가 있으면 적용하지 않는다. 적용 직전에도 원본 바이트 버전을 재확인한다. 유효한 XML과 UI 상속 계약을 검사한 뒤 변경을 적용하며, 게임 고유 의미는 프로젝트 검증으로 확인한다. 수정 권한을 켜고 보낸 요청은 미리보기 생성과 적용을 모두 허용하므로 중간 승인 창은 따로 띄우지 않는다. 변경은 작업 기록에서 확인·되돌릴 수 있다.

Codex는 프로젝트 파일이 없는 전용 작업 디렉터리에서 실행한다. 해당 대화의 셸·일반 실행·웹·이미지·브라우저·컴퓨터 도구·독립 MCP 연결·플러그인·외부 메모리/호스트 스킬 검색을 비활성화하는 설정을 보낸다. 네이티브 명령/파일 승인 요청은 거절하며 프로젝트 작업은 위 에디터 도구로 전달한다. 사용자 Codex 설정 파일이나 자격 증명은 복사·수정하지 않는다. 관리 정책과 충돌하는 설정은 연결 오류로 남으며 우회하지 않는다.

## 대화 수명과 기록

공식 프로토콜은 `initialize` → 계정 조회/로그인 → `thread/start` 또는 `thread/resume` → `turn/start` 순서다. 스트리밍 응답은 대화에 표시하고 완료된 답을 프로젝트 상태에 보관한다. 동적 도구는 에디터가 실행한 실제 결과를 돌려준다. 본문에 테스트 응답을 반환하는 제품 코드는 없다.

웹 대화나 에디터 공유 연결이 없어도 **로컬 Codex 대화**를 선택하면 이 흐름으로 독립 실행한다. Codex 자체의 계정 로그인과 모델 서버 연결은 필요하다. 성공한 요청은 `completed`, 취소한 요청은 `cancelled`, 실패한 요청은 `failed`로 저장하며 전송 중 상태에 남겨 두지 않는다. 웹 작업용 실행기를 사용한 뒤 로컬 대화로 돌아오면 원래 로컬 스레드를 다시 연결한다. 웹 대화 방식 선택도 게임팩에 저장된다.

게임팩 내부 `.packengine/<manifest 파일명>/conversations/`에는 원본 JSONL·메타데이터·마지막 선택을 저장한다. `LocalApplicationData/PackEngine/Projects/<프로젝트 경로 해시>/codex-thread.json`은 이 PC의 복구용 연결 정보로 유지한다. 다른 PC에서는 게임팩 기록을 해당 기기의 Codex sessions 저장소에 복원한 뒤 같은 ID를 이어간다. 인증은 각 기기의 공식 Codex CLI가 관리하며 게임팩에 복사하지 않는다. 재접속은 같은 대화 ID를 재개하고 **새 대화**는 다음 요청부터 새 ID를 만든다. API 키 계정이면 ChatGPT 로그인으로 바꾸도록 알리고 모델 요청은 보내지 않는다.

**작업 취소**는 진행 중인 turn에 중단을 요청하고 연결을 닫는다. 이미 적용된 파일은 자동 되돌림하지 않으며 변경 기록을 확인한다. 자동 연결이 켜져 있으면 다음 전송에서 다시 연결한다. 꺼져 있으면 **Codex 연결**을 누른다. 저장한 접근 설정에서 허용한 마지막 대화를 이어갈 수 있다. 연결 실패나 오류 응답을 성공한 작업으로 표시하지 않는다. 동시에 한 요청만 처리하며, 에디터와 별도 CLI가 같은 상태 폴더를 동시에 쓰는 것은 지원하지 않는다.

## 검증과 남은 실험

`tools/verify-resident.py`는 실제 골레맨서 사본으로 포인팅 스냅샷, 범위 제한, 충돌 방지, XML 수정과 복구, 지속 대화·스트리밍·취소·중단 전송을 검사한다. `tools/fixtures/codex-peer.py`는 통신 규약 검사용 프로세스이며 실제 모델을 흉내 낸 제품 기능이 아니다. `--codex /path/to/native/codex`를 주면 설치된 공식 CLI의 초기 연결과 같은 동적 도구 구성을 가진 임시 thread/start도 모델 호출 없이 확인한다.

```sh
python tools/verify-conversations.py --dotnet /path/to/dotnet --codex /path/to/codex
python tools/verify-resident.py --dotnet /path/to/dotnet --codex /path/to/codex
python tools/verify-editor.py --dotnet /path/to/dotnet
```

검증 스크립트는 Linux/.NET 10 기준이며 Windows WPF는 .NET Framework 4.8 대상으로 빌드한다. [검증 결과](EDITOR_VERIFICATION.md)에 자동 검사와 미확인 항목을 구분한다. 기존 에디터의 연결과 채팅은 사용자가 2026-10-01에 성공을 확인했다. 새 대화·접근 UI와 시작 창의 Windows 실제 조작, 영역 드래그와 모델의 자율 편집은 추가 실험 대상이다. 실행 중 게임 화면의 포인팅, 게임 객체 실시간 상태, 화면 캡처, DLL hot reload는 이번 구현에 없다.

Codex `0.159.2`의 실험적 app-server 동적 도구·환경 선택 스키마를 기준으로 구현했다. CLI를 임의로 업데이트하면 프로토콜이 달라질 수 있으므로 먼저 같은 검증을 다시 실행한다. 공식 근거: [구독 연결의 기록 제한](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations), [App server](https://developers.openai.com/codex/app-server/), [Codex 인증](https://developers.openai.com/codex/auth/), [해당 버전 소스](https://github.com/openai/codex/tree/rust-v0.159.2).
