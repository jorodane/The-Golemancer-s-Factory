# Confectory 대화 Timeline · YogiBox

2026-10-03 후속 구현. 이 문서는 이전 협업 문서의 수신자 선행 Yogi 첨부와 대화창 표시 동작을 대체한다. 변경안 승인·소유권·Helper 기억의 프로젝트 경계는 기존 계약을 유지한다.

## 대화

- Worker와 Helper는 동일한 투명 플로팅 UI를 쓴다. 회색 질문, 노란 답변, 좌우 이동, 최대 11개 Timeline 점, 캐릭터, 입력칸으로 구성한다. 답변이 길면 해당 말풍선 내부에서 읽는다. 전체 작업·도구 로그는 별도 기록에 남긴다.
- AI의 기본 상태는 접힘이다. 새 작업·새 발언은 대화창을 열지 않는다. 명시적으로 연 대화 여러 개를 함께 유지한다. 캐릭터를 드래그해 묶음을 이동하며, 응답 길이·상태 변화는 저장 위치를 바꾸지 않는다.
- 사이드바 단일 클릭/탭은 프로필, 더블클릭/더블탭은 대화 열기 또는 기존 대화 포커스다. 프로필은 읽음 처리하지 않는다. 테두리의 작업 상태와 파란 미확인 점은 별개다.
- Timeline은 현재 교환 앞뒤 다섯 개를 우선 표시한다. 양 끝에서는 남은 범위를 채워 최대 11개를 유지한다. Hover 또는 모바일 길게 누르기는 질문 우선 한 줄 미리보기다.
- 과거 교환 선택은 새 응답에도 유지한다. 이후 미확인 교환은 점과 다음 방향으로 알린다. 실제 선택된 교환의 메시지 ID만 읽음 처리한다. 프로젝트 위에 답변 토스트를 자동 추가하지 않는다.

## 수집 → 설명 → 봉인 → 전달

Windows 및 키보드가 연결된 Android에서 `Ctrl+Y`로 Yogi Mode를 켜고 끈다. 터치에서는 YogiBox의 `수집`을 사용한다. 클릭/탭은 EY, 범위 드래그는 LaY다. `Esc` 또는 Android 뒤로 키로 수집을 마친다.

| 내용 | 저장하는 것 | 다시 열었을 때 |
|---|---|---|
| EY | 프로젝트 ID와 요소의 고유 키 | 현재 대상 이동. 이름·소스 팩 변경 후에도 동일 ID를 찾음 |
| LaY | 캡처 시각, 실제 PNG, 크기와 SHA-256 | 당시 이미지 확대. 객체 Navigation으로 바꾸지 않음 |
| 설명 | 작성자의 요청·이유 | 모든 전달 대상에서 동일하게 보존 |

개념, 객체, 기능, 팩, 개념 Editor View 및 에디터팩 View의 UI 노드에 명시적 EY 키를 부여한다. 삭제된 프로젝트 요소는 누락으로 표시한다. 이름 없는 임시 네이티브 UI는 해당 인스턴스가 살아 있는 동안 이동할 수 있으며, 닫히거나 다시 생성된 뒤에는 닫힌/삭제된 대상으로 표시한다. 다른 프로젝트의 동일한 키로 이동하지 않는다.

YogiBox는 AI를 고르기 전에 수집한다. 제목과 설명을 적고 봉인하면 작은 박스가 된다. Windows 드래그 또는 Android 길게 눌러 드래그하여 펼친 AI, 사이드바 AI, 사람, 프로젝트 채팅, 신문고에 놓는다. 봉인된 박스의 더블클릭/더블탭은 다시 편집하기다. 한 박스는 EY 32개, LaY 최대 4개/총 768 KiB로 제한한다. 실제 캡처는 한 장 384 KiB까지 축소하며 전송 한도를 넘기면 범위를 줄이도록 안내한다.

각 전달은 봉인된 revision을 복사한다. 이후 편집·재봉인은 이전 대화·사건의 증거를 덮어쓰지 않는다. 받은 박스의 `내 YogiBox에서 수정`은 새 작성본을 만든다. 구조화된 박스를 텍스트나 이미지 첨부 하나로 평탄화하지 않는다.

소유한 AI에게 드롭하면 실제 요청으로 전달하며, 진행 중인 작업이 있으면 현재 세션의 대기열에 둔다. 재시작은 과거 요청을 자동 재실행하지 않는다. 다른 소유자의 AI는 공개 프로젝트 대화의 명시적 호출로 전달한다. 사람의 직접 전달은 TLS 호스트가 해당 사람에게만 라우팅하며, 개인 AI 대화는 자동 공유하지 않는다.

AI 요청을 만들 때 EY의 현재 내용을 다시 읽고 그 요청의 해시와 문맥을 고정한다. LaY는 보존된 실제 이미지 bytes를 Codex 및 OpenAI/Anthropic API의 이미지 입력으로 보낸다. 이미지 지원 여부·연결 오류는 실제 제공자 결과를 따르며 가짜 응답을 만들지 않는다. 공개 호출은 새 제공자 문맥에 공개 발언과 명시적으로 전달된 박스만 넣는다.

## 신문고

우하단 신문고는 실행·메뉴 옆에 항상 있다. 숫자는 `resolved/rejected/applied/closed`를 제외한 사건 수이며 최대 `99+`다. 읽거나 창을 열어도 감소하지 않는다. 강조색은 남은 사건의 최대 긴급도를 사용한다.

봉인된 박스를 드롭하면 긴급도와 등록만 묻는다. 기존 텍스트 사건도 지원한다. 신고의 박스를 열어 EY로 이동하고 LaY를 확인할 수 있으며, 해결 후에도 기록을 유지한다. 공동 프로젝트는 일반 사건의 상태와 원본 박스를 공유한다. 원격 사건 갱신은 원본 맥락을 덮어쓰거나 변경안 승인으로 바꿀 수 없고, 비공개 작업 체크포인트는 전송하지 않는다.

AI 도구 `packengine_yogi`는 `create/read/deliver/report`를 제공한다. `create`는 실제 인덱스 키와 호스트가 제공하는 실제 캡처만 받는다. AI의 작업 화면 캡처는 다른 참여자의 플로팅 대화와 편집 중인 박스를 가린 프로젝트 표면이다. 캡처를 지원하지 않는 호스트에서는 명확히 실패하며 이미지 데이터를 만들어내지 않는다. 신문고 긴급도와 YogiBox 전달은 실행·승인 권한을 부여하지 않는다.

## 검증

- Studio 회귀: Timeline 경계·과거 고정·개별 읽음, 봉인/재봉인과 전달 사본, EY 이름 변경/팩 이동/삭제, 캡처 hash/실제 PNG 크기, 사건 긴급도 감소·보존, AI 도구의 실제 캡처 경계.
- 네트워크: 실제 로컬 TLS 소켓의 구조화된 박스 왕복과 제3자에게 전달되지 않는 직접 라우팅.
- API fixture: 두 제공자의 실제 payload builder에 여러 LaY 이미지가 모두 포함되는지 검사. 유료 모델 응답 검증과 구분한다.
- Windows editor 및 native verification 컴파일, Android 전체 source 컴파일, 에디터팩/프로젝트 격리/전체 캠페인 회귀.

Linux 검증 환경에서는 Windows WPF GUI나 Android 기기를 직접 실행하지 않는다. 네이티브 드래그, DPI, 키보드/터치, 이미지 확대와 실제 모델의 시각 이해는 배포 기기에서 추가 확인해야 한다.

이미지 입력 형식 참고: [OpenAI Images and vision](https://developers.openai.com/api/docs/guides/images-vision), [Claude Vision](https://platform.claude.com/docs/en/build-with-claude/vision).
