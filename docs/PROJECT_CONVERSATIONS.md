# 로컬 대화 보관과 프로젝트에 저장

`StartEditor.exe`를 실행하고 **로컬 Codex 대화**를 선택하면 이 PC에서 마지막으로 사용한 대화를 이어간다. 대화와 복구 기록, 로컬/웹 방식 선택은 기본적으로 사용자 데이터 폴더에 보관한다. 프로젝트 열기, 연결, 기록 조회, 응답 완료, 취소, 연결 끊김은 프로젝트의 대화 파일을 생성하거나 갱신하지 않는다.

**프로젝트에 대화 저장**은 현재 대화의 원본 스냅샷을 프로젝트에 보관하는 명시적 작업이다. 로컬 대화 상단과 **대화·접근** 탭에서 사용할 수 있다. 응답이 끝난 뒤 저장하며 선택한 한 대화만 포함한다. 한 번 저장해도 자동 저장이 켜지지는 않는다. 이후 내용까지 옮기려면 다시 저장한다.

## 다른 기기로 옮기기

1. 옮길 로컬 대화를 열고 응답이 끝나면 **프로젝트에 대화 저장**을 누른다.
2. **프로젝트에 저장한 대화 폴더**에서 결과를 확인한다. 게임팩의 `.packengine` 폴더를 포함해 복사하거나 Git으로 공유한다.
3. 다른 PC에서 프로젝트를 열고 로컬 Codex 설치·로그인을 준비한다. 기기별 접근 설정을 따른다.
4. **대화·접근 → 게임팩의 로컬 대화**에서 저장된 대화를 선택한다. 기존 PC의 Codex 저장소가 없어도 프로젝트의 원본으로 복원한다.
5. 이어지는 대화는 새 PC에만 보관한다. 프로젝트 스냅샷은 다시 저장할 때만 갱신한다.

기존 버전이 프로젝트에 자동 저장했던 대화도 그대로 읽을 수 있다. 기존 파일을 자동 삭제하거나 옮기지 않으며, 읽기에는 프로젝트 잠금 파일이나 쓰기 권한을 요구하지 않는다. 이 PC에 같은 대화의 기록이 있으면 그 기록을 사용한다. 로컬 선택은 프로젝트에 저장된 예전 선택보다 우선한다.

## 저장 위치

| 경로 | 내용과 저장 시점 |
|---|---|
| 사용자 `PackEngine/Projects/<프로젝트 경로 해시>/conversation.xml` | 이 PC의 대화 방식과 프로젝트 연결 식별자 |
| 같은 폴더의 `conversations/` | 자동 보관하는 Codex 원본 스냅샷·메타데이터·로컬 선택 |
| 같은 폴더의 `codex-thread.json` | 이 PC에서 재접속할 대화 ID·모델 |
| 같은 폴더의 `web-codex/conversations/` | 에디터 공유 작업용 Codex 실행기의 로컬 기록 |
| `<게임팩>/.packengine/<manifest 파일명>/conversation.xml` | 명시적으로 저장한 대화/주소의 이동 가능한 프로젝트 ID·설정 |
| 같은 폴더의 `conversations/<thread ID>.json` | 사용자가 저장한 대화 이름·모델·원본 파일 이름·해시 |
| `conversations/<thread ID>-<해시>.jsonl` | 저장 시점의 실제 Codex 원본 기록 |
| `conversations/active.txt` | 마지막으로 프로젝트에 저장한 대화 ID |
| 사용자 `PackEngine/assistant-settings.json` | 이 PC의 연결·기록 접근 허용 및 차단 |

Windows 사용자 데이터 루트는 `%LOCALAPPDATA%`다. **이 PC의 대화 폴더**는 자동 보관 위치를 연다. **프로젝트에 저장한 대화 폴더**는 이미 저장된 위치만 열고 빈 프로젝트 폴더를 만들지 않는다. CLI에서 `--state`를 지정하면 로컬 상태와 복구본은 그 폴더에 둔다.

프로젝트에 저장한 원본에는 질문·답과 사용한 프로젝트 문맥·도구 기록이 포함된다. 로그인 토큰, `auth.json`, 전역 Codex 설정과 기기별 작업 권한은 복사하지 않는다. 에디터는 `.gitignore`나 Git 추적 설정을 변경하지 않고 대화를 자동 커밋하지 않는다. 명시적 저장을 사용하지 않으면 프로젝트 내부 대화 파일도 추가되지 않는다.

## 복원과 충돌 처리

Codex 원본 rollout JSONL을 기기의 `sessions` 저장소에 복원하고 공식 `thread/resume`으로 같은 ID를 이어간다. 채팅 본문을 새 질문으로 다시 보내는 방식은 아니다. 원본 바이트는 변경하지 않고 현재 작업 경로·도구·권한은 재개 옵션으로 전달한다.

기기별 자동 보관과 명시적 프로젝트 저장 모두 스냅샷을 먼저 기록한 뒤 메타데이터를 원자적으로 교체한다. 해시·프로젝트 ID·대화 ID·에디터 originator를 검증하며 연결 폴더를 거부한다. 원본 크기는 대화별 최대 64MiB다. 기기별 보관에 실패하면 Codex 원본은 유지하고 오류를 표시한다.

프로젝트에 다시 저장할 때 기존 프로젝트 기록이 새 로컬 기록의 앞부분인지 확인한다. 다른 기기에서 서로 갈라졌거나 저장 중 다른 작성자가 바꾸면 덮어쓰지 않는다. 프로젝트의 갈라진 스냅샷 때문에 이미 보관한 로컬 대화 사용을 중단하지는 않는다. 기록 접근을 끄면 이전 기록을 읽지 않고 요청마다 새 대화를 만든다. 접근 차단은 기록 삭제나 무저장 모드가 아니다.

## CLI

`codex-chat`, `codex-history`, `codex-threads`는 프로젝트 대화를 자동 저장하지 않는다. 기존 `--project-conversations` 옵션은 프로젝트에 저장한 기록을 조회·복원할 수 있게 하며 자동 저장을 허용하지 않는다. 다음 명령만 선택한 대화를 프로젝트에 저장한다.

```sh
dotnet PackEngine.Tool.dll codex-save --project Game.packproject --provider PackEngine.Assistant.Codex.dll --thread <대화-ID>
```

`--thread`를 생략하면 현재 로컬 선택을 저장한다. 연결된 에디터와 CLI가 동일한 로컬 상태 폴더에 동시에 쓰지 않도록 자동화에는 별도 `--state`를 지정한다.

## 검증

```sh
python tools/verify-conversations.py --dotnet /path/to/dotnet --codex /path/to/native/codex
```

프로젝트 바이트 비교로 일반 대화·목록·조회·취소·연결 끊김에 프로젝트 쓰기가 없는지 검사한다. 명시적 저장, 다시 저장하기, 새 기기로 이동·복원, 로컬 선택 우선, 접근 차단, 충돌 보존도 검사한다. 통신 fixture는 제품 코드와 분리한다. 선택적인 공식 Codex 검사는 로그인이나 모델 추론 없이 원본 복원·재개를 확인한다. 실제 Windows 화면 조작은 별도 검증이 필요하다.

## ChatGPT 주소 연결

ChatGPT 웹 로그인과 대화 기록은 웹 서비스가 관리한다. **대화 주소 저장 → 이 게임팩과 연결**로 명시적으로 저장한 프로젝트·대화 주소는 이동 가능한 프로젝트 메타데이터에 남는다. 단순히 로컬/웹 방식을 전환하는 것은 기기별 설정만 바꾼다. 주소 저장은 파일 접근·모델 실행 권한을 부여하지 않는다. [웹 연결](CHATGPT_BRIDGE.md)을 따른다.
