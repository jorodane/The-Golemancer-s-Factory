# 게임팩의 대화 선택과 여러 기기에서 이어가기

`StartEditor.exe`를 실행한다. **새 게임팩**에서 빈 폴더와 `.packproject` 이름을 고르면 기본 객체팩을 만들고 대화 방식을 묻는다. 기존 게임팩도 아직 선택하지 않았다면 처음 한 번 묻는다. 오른쪽 **게임팩 대화 방식 선택**에서 언제든 변경한다. 취소하면 AI 연결 없이 문서를 편집할 수 있다.

| 선택 | 대화 위치와 동작 |
|---|---|
| 로컬 Codex 대화 | 에디터에서 대화한다. 시작 시 기기별 접근 설정에 따라 연결하고 마지막 대화를 불러온다. 원본 기록은 게임팩 안에 보관한다. |
| 기존 ChatGPT 채팅·프로젝트 연결 | 기존 주소와 이름을 저장한다. **ChatGPT 열기**로 같은 장소를 연다. 대화는 ChatGPT에 남고, 실제 에디터 작업은 별도의 [MCP 연결](CHATGPT_BRIDGE.md)을 사용한다. |

로컬 방식을 처음 선택하면 필요한 Codex 설치를 준비한다. Node.js/npm이 없으면 공식 설치 페이지를 연다. 설치 뒤 **Codex 설치 확인·다시 연결**을 누른다. 로그인은 공식 Codex의 ChatGPT 로그인 화면을 사용한다. 기존 ChatGPT 방식에서는 이 설치가 필요하지 않다.

## 로컬 대화를 옮기는 방법

1. 진행 중인 응답을 마치고 게임팩에 저장됐는지 실행 기록을 확인한다. 취소·연결 끊김도 기록된 원본을 보관하려고 시도하며 실패하면 표시한다.
2. 에디터를 닫고 게임팩 폴더 전체를 복사하거나 사용 중인 폴더 동기화를 완료한다. **대화 저장 폴더**로 위치를 확인할 수 있다.
3. 다른 PC에서 그 `.packproject`를 연다. 설치와 로그인을 준비하면 마지막 대화와 목록이 복원된다. 부모 폴더 이름과 절대 경로가 달라도 된다.
4. **대화·접근 → 게임팩의 로컬 대화**에서 대화를 눌러 이어간다. 이전 PC 방식의 기록은 **이 PC**라는 표시로 나오며, 열면 게임팩에도 보관된다. **더 보기**로 이전 기록을 계속 조회한다.

이 기능은 폴더에 기록을 저장하고 다시 불러오는 기능이다. 클라우드 계정이나 동기화 서비스를 자동 설정하지 않는다. 같은 대화를 두 PC에서 동시에 진행하는 병합 기능도 없다. 이전 기록에서 각각 갈라진 파일을 발견하면 양쪽 원본을 유지하고 연결을 멈춘다. 최신 폴더 복사가 완전히 끝난 뒤 하나의 기기에서 이어가거나 새 대화를 선택한다.

설정과 기록은 다음과 같이 나뉜다.

| 경로 | 내용 |
|---|---|
| `<게임팩>/.packengine/<manifest 파일명>/conversation.xml` | 대화 방식, 이동 가능한 프로젝트 ID, 기존 ChatGPT 주소와 이름 |
| 같은 폴더의 `conversations/<thread ID>.json` | 대화 이름·모델·원본 파일 이름·해시 |
| `conversations/<thread ID>-<해시>.jsonl` | Codex가 기록한 실제 대화 원본. 질문·답·도구 작업 등 재개에 필요한 기록 |
| `conversations/active.txt` | 마지막으로 선택한 대화 ID |
| 사용자 폴더의 `PackEngine/assistant-settings.json` | 이 PC의 접근 허용·차단 및 작업 범위 |
| 사용자 폴더의 `PackEngine/Projects/<경로 해시>/` | 이 PC의 편집 초안·작업 기록·복구용 Codex 연결 정보 |

대화 원본에는 대화 중 사용한 프로젝트 문맥이 포함된다. 대화를 함께 옮길 때는 `.packengine` 폴더를 포함하고, 코드만 공유할 때는 별도로 제외한다. 에디터가 Git 추적 설정을 바꾸거나 대화 파일을 자동 커밋하지 않는다. `auth.json`, 로그인 토큰, 전역 Codex 설정, 프로젝트 수정·실행 권한은 게임팩에 복사하지 않는다. 기기별 로그인과 권한은 각 기기에 남는다.

## 저장과 복원 방식

Codex 0.159.2의 원본 rollout JSONL을 완료 시 보관한다. ID만 저장하거나 채팅 본문을 새 질문으로 붙여 넣는 방식이 아니다. 다음 기기에서는 선택한 게임팩 기록만 기기의 Codex `sessions` 저장소에 복원하고 공식 `thread/resume`으로 같은 대화를 재개한다. 원본 JSONL 내용은 변경하지 않으며, 재개 옵션의 작업 경로·도구·권한은 현재 에디터에 맞춰 적용한다. 공식 `thread/resume.path`만으로는 비어 있는 저장소에서 복원되지 않아 sessions 인벤토리 복원이 필요하다.

스냅샷 파일을 먼저 기록하고 메타데이터를 원자적으로 교체한다. 해시·프로젝트 ID·대화 ID·에디터 originator를 검증하고 연결 폴더를 거부한다. 같은 PC의 중복 작성자는 배제한다. 동기화로 관측한 스냅샷이 바뀌거나 기기 기록이 서로 갈라지면 기존 파일을 덮어쓰지 않는다. 원본은 대화별 최대 64MiB이며, 보관 실패 시 이 PC의 Codex 원본을 유지하고 오류를 표시한다. 기록 접근을 끄면 기존 기록은 읽지 않고 요청마다 새 대화를 만든다. 이 설정은 기록 삭제나 무저장 모드가 아니다.

`PackEngine.Tool`에서는 `--project-conversations`를 지정해 같은 저장 방식을 사용할 수 있다. 지정하지 않은 CLI 호출은 기존 기기별 저장 방식을 유지한다. 자동화와 에디터가 같은 게임팩 대화를 동시에 사용하지 않는다.

## 검증

```sh
python tools/verify-conversations.py --dotnet /path/to/dotnet --codex /path/to/native/codex
```

새 게임팩, 선택 유지, 폴더 이동, 접근 권한 분리, 기록 충돌, 손상 파일, 취소·연결 끊김을 검사한다. 통신 fixture는 테스트 전용이며 제품에 포함하지 않는다. 별도로 공식 Codex에서 생성한 기록을 옮기고 기존 PC 저장소를 삭제한 뒤 실제 제공자에서 복원·조회하고 공식 재개까지 확인한다. 이 검사는 로그인이나 모델 추론을 하지 않는다. Windows UI 조작, 서로 다른 물리적 Windows PC, 클라우드 동기화 서비스, 로그인 후 실제 모델의 이어지는 응답은 이 환경에서 시험하지 않았다.
