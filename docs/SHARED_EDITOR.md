# 웹 대화와 로컬 Codex의 에디터 작업

`StartEditor.exe`로 게임팩을 열고 **에디터 연결**을 누른다. 이 연결은 대화 주소 저장과 별개이며 ChatGPT 프로젝트나 대화 URL을 입력할 필요가 없다. 수정할 게임 객체팩·에디터팩과 실행·검증 허용 범위를 에디터에서 선택하고, PackEngine Links 화면에서 로그인 계정과 범위를 확인한다. 연결은 해당 PC의 게임팩에서 8시간 유지되고 **연결 중지**로 종료한다.

## 자료 공유

- **상태 공유**: 열린 문서의 상대 경로, 해시, 초안·외부 변경 여부와 객체팩 목록. 본문은 포함하지 않는다.
- **Exactly Yogi**: 에디터 작업 영역의 요소를 클릭하면 현재 열린 ChatGPT 입력창에 `.txt` 파일을 첨부한다. Ctrl+클릭은 여러 요소를 모으고 **선택 첨부**로 붙인다. 일반 UI는 종류·이름·라벨·영역을, 색인된 객체는 해당 정의와 버전을 포함한다. 관련 없는 열린 문서나 팩 목록은 첨부하지 않는다.
- **Look At Yogi**: 요소를 클릭하거나 범위를 드래그하면 현재 ChatGPT 입력창에 PNG를 첨부한다. 에디터 작업 영역에 한정하며 PC의 다른 창을 캡처하지 않는다.
- **문서 공유**: 현재 열린 문서 하나의 본문을 최대 12,000자 공유한다. 잘린 내용과 미저장 초안을 표시한다.

Yogi는 별도 XML·이미지 확인창을 열지 않는다. 기존 입력 문장과 첨부를 유지하며, ChatGPT 입력창에서 첨부를 확인하고 사용자가 직접 전송한다. **에디터 연결** 없이도 첨부할 수 있다. 자동 첨부를 확인하지 못하면 웹 패널 위에 같은 파일이 남고, 파일명을 입력창으로 끌어 넣거나 **파일 복사**, **첨부 다시 시도**를 사용할 수 있다. 재시도 전 입력창에 이미 붙었는지 확인한다. 대화나 게임팩이 바뀌면 진행 중 첨부를 중단한다. 상태·문서 공유는 기존 확인창을 유지한다.

자료는 캡처 당시의 고정된 버전이며 에디터 화면을 실시간으로 관찰하는 기능이 아니다. 상태 목록에는 최대 100개 문서, 지정 대상에는 최대 64개 요소를 포함한다. PNG는 긴 변 최대 1,600픽셀, 384 KiB 이하로 축소한다. 첨부 파일은 PC 에디터 상태 폴더의 `chat-attachments`에 남는다. 이미 **에디터 연결**을 허용한 경우에는 첨부한 스냅샷을 그 연결에도 공유해 Codex가 같은 버전을 참조하게 한다. 이 연결의 공유 내용과 작업 결과는 로그인 계정에 귀속된 서버 저장소에 남는다. 계정 쿠키나 로그인 토큰은 대화·게임팩에 내보내지 않는다.

자동 첨부는 WebView2의 DevTools 파일 입력과 브라우저의 파일 붙여넣기 이벤트를 사용한다. 현재 입력창만 다루며 대화 기록이나 ChatGPT 내부 API를 읽지 않는다. 페이지 구조가 바뀌거나 첨부가 비활성화된 경우에는 직접 끌어 넣기를 사용한다. 첨부 표시 확인은 ChatGPT 서버의 업로드 완료나 메시지 전송 완료를 뜻하지 않는다.

## 웹 대화에서 작업 요청

기존 PackEngine Links 플러그인은 주소 저장 도구와 다음 에디터 도구를 제공한다.

| 도구 | 동작 |
|---|---|
| `packengine_editor_sessions` | 같은 계정에서 명시적으로 연결한 에디터, 응답 시각, 권한과 최근 공유 자료 확인 |
| `packengine_editor_context` | 공유 자료 조회. 본문과 이미지는 필요한 경우에만 요청 |
| `packengine_codex_request` | 구체적인 작업과 이 대화의 관련 합의·제약을 로컬 Codex에 전달 |
| `packengine_codex_result` | 작업의 실제 상태·진행·결과·변경 기록 조회 |
| `packengine_codex_cancel` | 대기 작업 취소 또는 실행 중 작업의 취소 요청 |

웹 ChatGPT가 작업에 필요한 문맥을 `context`로 전달하고, 로컬 Codex가 에디터의 실제 도구를 실행한다. 로컬 Codex가 웹 채팅 전체를 자동으로 읽거나 두 대화 기록을 동기화하지 않는다. 포인팅한 자료가 관련되면 이미 조회한 `snapshotId`를 함께 전달한다. 그 뒤 문서가 바뀌었다면 실행 전에 다시 공유하도록 알린다. 수정·빌드·에디터팩 재로딩은 연결 때 정한 범위 안에서만 수행된다.

## 중단과 재시도

`queued`와 `running`은 완료가 아니다. 결과 상태는 `succeeded`, `failed`, `cancelled`, `interrupted`로 구분한다. 연결이 끊겼다는 이유로 성공이나 실패를 추측하지 않고 결과와 에디터 응답 시각을 함께 확인한다.

같은 요청을 다시 전달할 때는 같은 `requestKey`를 사용한다. 동시에 재시도해도 하나의 작업으로 저장한다. 에디터는 실행권을 먼저 기록하고 완료 결과를 로컬에 저장한 뒤 전달한다. 일시적인 전달 실패는 같은 연결에서 재시도하며, 재시작 후 실행 도중이던 작업은 `interrupted`로 보고하고 자동 재실행하지 않는다. 취소나 연결 종료는 이미 적용된 변경을 되돌리지 않는다. 이미 적용된 변경은 에디터 변경 기록에서 확인한다.

새 작업의 로컬 기록은 `queued`로 시작한다. 공통 `SharedEditorTaskRunner`가 실행권 요청 → `started` 저장 → 실제 실행 → 결과 저장 → 서버 전달을 담당한다. 서버가 실행권을 확인하기 전에는 실행하거나 완료 결과를 만들지 않는다. 완료 응답을 잃어버려도 같은 결과만 재전달하며 모델 작업을 다시 실행하지 않는다. 웹 실행용 Codex는 `web-codex`/`web-executor`에, 로컬 대화용 Codex는 원래 대화 폴더에 연결한다. 모드를 바꾸거나 로컬 대화 중 웹 작업을 처리해도 두 대화의 스레드를 재사용하지 않는다.

## 검증 범위

`tools/verify-resident.py`는 실제 프로젝트 사본에서 공유 문맥·버전·팩 범위, XML 적용·빌드·되돌리기, Codex 프로토콜과 복원·취소를 검사한다. 프로토콜 fixture와 공식 CLI 연결 검증은 실제 모델 응답과 구분한다. 공유 계약 fixture는 `TestResults/resident/shared-contract.json`에 생성된다. 서버 검사는 실제 SQLite 질의와 이 fixture로 계정 분리·PNG·작업 재시도·취소를 검증한다.

Windows net48 컴파일과 프로토콜 검사는 WPF 화면 클릭이나 WebView 로그인을 검증하지 않는다. 사용자 Windows 에디터와의 실제 왕복은 별도로 확인해야 한다.

2026-10-01에는 별도로 실제 로그인된 Codex 모델도 검증했다. 로컬 대화는 두 턴에 걸쳐 이전 계획을 기억하고, 테스트 사본의 버튼 `fontSize`를 13에서 15로 수정한 뒤 해당 팩 XML·UI 계약 검증을 완료했다. 웹 작업용 호스트는 전달된 `WEB-CONTEXT-73` 문맥과 스냅샷을 실제 모델에 보내고 `packengine_read` 결과를 `succeeded`로 저장·반환했다. 이 웹 검사의 전송 구간은 명시적 fixture이고 사용자 Windows 에디터의 실시간 왕복은 검증하지 않았다. 실제 모델 검사는 자동 실행하지 않으며 `tests/PackEngine.SharedFlow.Verification`의 `--live copied-project.packproject state-directory native-codex`로 명시적으로 실행한다.

Windows 첨부 확인: 채팅에 문장과 기존 파일을 남긴 상태로 Exactly Yogi를 눌러 대상 하나를 고른다. 확인창 없이 텍스트 파일이 추가되고 기존 입력이 유지되는지 확인한다. Look At Yogi로 범위를 지정해 이미지 미리보기가 추가되는지, 전송 전 삭제할 수 있는지 확인한다. Ctrl+클릭 여러 대상은 **선택 첨부**에서 한 파일로 전달한다. 첨부 중 다른 대화로 이동하거나 입력창이 없는 페이지에서 시도하면 완료로 표시하지 않고 같은 파일의 직접 첨부 경로를 남겨야 한다.
