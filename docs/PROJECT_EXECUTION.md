# 팩 기반 엔진 배포와 프로젝트팩 실행

엔진 자체도 팩으로 만든다. 엔진을 팩 구조에서 떼어 내거나 기본 UI DLL을 코어 라이브러리에 합치지 않는다. 배포 시 `editor/engine.xml`에서 선택한 엔진 팩과 플랫폼 호스트를 한 배포본으로 빌드한다. 사용자 프로젝트는 이 설치된 엔진 위에 자식 팩을 조합해서 실행한다.

## 빌드와 설치

`BuildEditor.bat`는 기존 솔루션을 빌드한 뒤 `PackEngine.Tool bundle-engine`으로 `editor/Builds/Windows/Engine`을 만든다. Android 빌드는 같은 명세를 사용해 고정된 `Engine.zip` 배포 묶음을 APK 자산에 넣는다. 설치할 때 해시를 검사하고 `Engine/`에 푼다. Windows는 배포 폴더의 스냅샷, Android는 APK에서 설치한 스냅샷을 사용한다. 저장소의 `editor/Packs`는 엔진 개발용 소스이며 실행 중인 배포본의 편집 대상이 아니다.

`distribution.xml`에는 엔진 ID·릴리스·실행 프레임워크, 팩 구성, 실제 DLL/XML/소스 파일의 SHA-256을 기록한다. 선언과 공개 소스의 호환성 해시는 줄바꿈 차이를 정규화해서 Windows와 Android가 공유한다. 파일 검사는 실제 설치 바이트를 기준으로 한다. 팩 DLL을 실행하지 않고 배포본을 만들고 검사한다.

새 실행을 준비할 때 설치된 엔진 파일을 검증한다. 배포된 엔진 팩의 빌드·패치·파일 추가는 편집 API에서도 막는다. 엔진 변경은 소스 팩을 수정한 다음 배포본 전체를 다시 빌드하는 작업이다. Golemancer의 동결 SDK와 게임 계약은 이 변경으로 갱신하지 않는다.

## 프로젝트 세션

`ProjectPackSession`은 고정 엔진 팩과 프로젝트/공용 팩을 조합한다. 엔진 ID를 같은 ID의 프로젝트팩으로 덮어 쓸 수 없고, 호스트 계약·런타임 DLL을 프로젝트 종속성으로 제공할 수 없다. 새 ID의 팩에서 기존 정의를 상속하고 지원되는 필드·슬롯을 재정의하거나 기능을 추가한다. 기존 계약 보존과 상속 충돌 검사는 그대로 적용한다.

각 세션은 별도의 모듈 수명을 가진다. 같은 엔진과 같은 프로젝트를 중첩 실행해도 다른 세션의 DLL 상태를 공유하지 않는다. 같은 세션의 XML 변경은 모듈을 재사용하고, 코드 변경은 해당 의존 모듈을 새로 준비한다. 후보를 먼저 준비하고 네이티브 화면 검증을 마친 뒤 확정하므로 잘못된 후보는 기존 실행을 교체하지 않는다. 프로젝트를 전환하거나 닫으면 해당 세션을 해제한다.

Windows는 기존 외부 worker, Android는 기존 앱 내부 DLL 실행기를 사용한다. 이 수명·구성 경계는 .NET 코드의 보안 샌드박스가 아니다. 실행 동의를 받은 프로젝트 코드에는 기존 호스트의 권한이 적용된다.

## 프로젝트팩 파일

**프로젝트팩 내보내기**는 `.projectpack` ZIP에 확정된 프로젝트 문서와 활성 프로젝트/공용 팩의 XML·소스·실행 DLL을 담는다. 엔진 팩은 포함하지 않고 `project-run.xml`에서 설치된 엔진의 호환성 버전을 참조한다. 다른 프로젝트로 옮기는 공용 종속 팩도 프로젝트의 실행 구성에 포함된다. 원래 게임 빌드와 모바일 문서 ZIP 내보내기는 별도의 기능으로 유지된다.

가져오기는 해시·경로·크기·팩 등록·엔진 호환성을 먼저 검사하고 파일만 준비한다. 문서와 DLL 실행은 사용자가 **열기·실행**을 선택한 뒤 진행한다. 일반 `.packproject`/문서 ZIP 열기는 여전히 프로젝트 명령이나 알려지지 않은 DLL을 실행하지 않는다.

XML만 있는 프로젝트팩은 프레임워크를 `any`로 선언하므로 같은 엔진 버전의 Windows/Android에서 사용할 수 있다. DLL이 있는 프로젝트팩은 현재 호스트의 `net48` 또는 `net10.0` 대상과 일치해야 한다. `net48` DLL을 Android용 DLL로 자동 변환하지 않는다. Android 내부 C# 컴파일러는 이번 실행 구조에 추가하지 않았으며, 기존 PC 팩 빌드 경로를 사용한다.

이번 실행 대상은 Confectory의 `editor-1` 프로젝트팩이다. 게임의 네이티브 클라이언트·도메인 계약·콘텐츠/이미지 전체를 일반 실행기에 자동 변환하는 게임 배포 형식은 아니다.

## 확인

`tools/verify-editor-packs.py`는 실제 DLL로 중첩 세션 상태 분리, XML 재적용, 잘못된 후보의 이전 실행 보존, 엔진 ID/런타임 대체 거부, 읽기 전용 검토, 내보내기/가져오기/재실행, 파일 변조·대상·엔진 버전 불일치와 준비 폴더 정리를 검사한다. CI는 Windows 네이티브 UI, Android 빌드/엔진 자산, 기존 작업자·검토 회귀 및 게임 SDK 격리/전체 캠페인을 함께 검사한다.
