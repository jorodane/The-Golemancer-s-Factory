# 프로젝트 개념 공간

프로젝트 내부의 일반 화면은 AI 사이드바, 하단 프로젝트 채팅, 중앙 작업 공간, 오른쪽 아래 실행·탐색 버튼으로 구성한다. 상단 메뉴·파일 탐색기·Inspector·Console·상태줄은 상시 노출하지 않는다. 기존 프로젝트의 메인 화면 팩은 유지하고 새 프로젝트는 빈 메인 화면과 Main Pack으로 시작한다.

## 탐색과 편집

- **≡ → 카테고리 → 개념:** 스키마를 공유하는 객체를 편집한다. Source Pack별 필터와 묶음 정렬을 지원한다.
- **개념:** 카테고리와 개념을 분류 방향의 맵으로 표시한다. Variation이 있는 개념은 이중 원 표시를 사용하며 별도 단계에서 탐색한다. Windows에서 Hover와 Shift는 정방향·역방향 참조를 표시한다. 개념의 스키마 편집은 원래 맵 위에서 열고 빈 공간이나 Escape로 닫는다.
- **객체:** 문자열·숫자·논리값·개념 참조, 반복 항목, 중첩 복합 항목과 기능 계약을 편집한다. 여러 Editor View가 같은 객체 값을 사용하며 카드·입출력 아이콘 슬롯·에디터팩 보기를 지원한다. 유효한 사용자 View가 없으면 범용 스키마 테이블로 돌아간다.
- **기능:** Namespace와 논리 주소를 따라 탐색한다. 이름·입력 매개변수 이름과 타입·반복 여부·반환 타입이 맞는 구현을 계약에 연결한다. **구현**은 실제 C# 소스를 열고 구문과 public static 시그니처를 검사한다. Windows의 팩 빌드는 연결된 프로젝트에서 실제 DLL을 만든다.
- **팩:** 이름·설명·Namespace·의존성을 확인하고 새 팩을 만들거나 선택한 요소를 이주시킨다. 요소가 서로 의존하면 관련 요소를 함께 옮길 수 있다.

## 소유권과 저장

프로젝트의 `ConceptSpace`는 팩별 스키마, 객체, View 문서를 별도로 연결한다. `Source Pack`은 시스템 메타데이터이며 사용자 스키마 필드에 끼워 넣지 않는다. 개념·객체·기능·View·카테고리는 이름이나 경로와 독립된 고정 ID를 사용한다. Namespace를 바꾸거나 팩을 옮겨도 ID와 참조를 유지한다.

팩 이주는 해당 요소의 소유 문서를 변경하고 타입·상속·객체 참조·기능 연결에 따른 의존성을 다시 계산한다. 일반 문자열을 우연히 ID와 같다는 이유로 의존성으로 취급하지 않는다. 의존성 순환은 이주를 거부하고 이전 소유권을 복구한다. 구현 코드의 실제 파일 위치가 바뀌지 않아도 새 소유 팩의 빌드 프로젝트에서 그 소스를 연결한다.

열기는 파일을 쓰거나 DLL·명령을 실행하지 않는다. 저장은 변경되는 파일뿐 아니라 읽었던 문서들의 버전을 검사하고, 열려 있는 미저장 문서나 읽기 전용 팩을 덮어쓰지 않는다. View만 추가할 때 스키마와 객체 데이터는 그대로 유지한다. 충돌이 나면 최신 프로젝트를 다시 열어 변경을 검토해야 한다.

## 실행

**▶**는 구성된 프로젝트 실행 대상을 시작하며 **■**는 실행을 종료한다. 실행 구성이 없는 빈 프로젝트는 빈 미리보기 화면을 연다. 객체나 기능이 있는 프로젝트는 실행 대상·화면을 연결해야 한다. 편집 중인 코드를 자동 실행하지 않는다. Android는 설치된 프로젝트 앱을 명시적으로 실행하고 Windows는 기존 ProjectRunner를 사용한다.

## 검증

`python tools/verify-studio.py --dotnet <dotnet> --network`는 개념·중첩 값·Variation·View·고정 ID·팩 이주·읽기 전용/동시 변경 거부와 실제 기능 DLL 빌드·호출을 검증한다. Windows 네이티브 검증에는 사이드바·동시 대화·개념 페이지 위 표시·독립 닫기·읽음 시점 검사를 포함한다. Windows GUI 실행 및 Android 실기기 조작은 각 플랫폼에서 별도로 확인한다.
