# 검증 기록

## Android 플랫폼·입력 모듈 검증 (2026-09-30)

공유 엔진 전체 검증 **449 PASS**, 첫 챕터 12개 퀘스트 및 동굴 입구 개방, 독립 TeaBreak DLL 확장 검증을 통과했다. net48 전체 솔루션과 독립 예제, net10.0 공유 엔진과 독립 예제, net10.0-android Release APK는 모두 경고 0·오류 0으로 빌드했다.

- Android API 29 x86_64 에뮬레이터에 Release APK를 설치하고 **ANDROID_SMOKE_PASS**를 확인했다. 앱 안에서 외부 DLL 로딩, 호스트의 콘텐츠 모듈 참조 부재, 앱 전용 저장·복원, 모든 스프라이트 소스 디코딩을 검사했다.
- 실제 Android MotionEvent를 통해 가상 스틱과 두 번째 손가락 버튼의 동시 입력, 두 번째 손가락 해제 후 스틱 유지, 터치 취소 시 눌림·대기 이벤트 제거를 확인했다. 버블이 열린 동안 뒤쪽 HUD 히트 영역이 제거됨을 확인했다.
- 입력 계약 회귀 검사는 Windows/Android 키 이름 차이, 타깃별 덮어쓰기와 명시적 해제, touch 바인딩 변경, 키보드·터치 공존, 게임패드 연결 해제, 대각선 정규화·데드존을 포함한다. TeaBreak DLL이 키보드·게임패드 바인딩을 별도로 선언하고 기존 호스트 참조 변경 없이 실행됨을 확인했다.
- APK에는 `arm64-v8a`와 `x86_64` 런타임 및 별도 asset 형태의 콘텐츠 DLL 13개를 포함했다. 런타임 assembly store/압축을 복구하여 `compressed_assembly_count` 누락을 해결했고, `AndroidEnableMarshalMethods=false`로 Release JNI 시작 메서드 등록 누락을 해결했다.
- 이전 테스트 AVD의 임시 디스크가 쌓여 저장공간을 소진한 상태도 확인했다. 사용하지 않는 테스트 디스크만 정리한 뒤 같은 프로젝트를 정상 빌드했다.

검증 환경은 .NET SDK 10.0.401, Android workload 36.1.2, SDK API/build-tools 36, JDK 21이다. 실제 ARM64 휴대폰·물리 게임패드·Android 8 및 최신 Android에서의 실행, 실기기 성능과 장시간 플레이는 아직 검증하지 않았다. Windows WPF 실제 창 실행도 이번 Linux 환경에서는 수행하지 않았다. 재현 명령은 [Android 안내](ANDROID.md)에 있다.

## 저장소에서 바로 실행하는 배포

- `Builds/Windows`에 압축을 풀어둔 EXE·엔진 의존 DLL·검증 프로그램을 제공한다. 모듈 DLL은 `Content/Packs/*/Bin/net48`에 두어 기존 `pack.xml`로 로드한다.
- `Start.bat`과 `Verify.bat`은 SDK나 재빌드 없이 이 파일을 실행하며, 게임과 검증이 저장소 루트의 `Content`를 공유한다.
- `Build.bat`은 Release 빌드 뒤 `tools/Publish.proj`로 동일한 실행 폴더를 갱신한다. 게시 대상은 EXE·DLL·설정과 빌드 메타데이터이며 이미지·저장 파일은 복사하거나 삭제하지 않는다.
- 이미지 제외 규칙은 제거했다. 이미지 업로드는 사용자의 Git 환경에서 진행하며, 이번 빌드 배포 커밋에는 이미지 파일을 포함하지 않는다.
- 커밋 대상만 복사한 별도 저장소 구조에서 net48 모듈 12개와 필수 이미지 경로 77개를 확인했다. 이미지 79개와 테스트 세이브를 먼저 로컬에 둔 뒤 파일 갱신을 적용해 내용이 유지됨을 확인했다. 실행·검증 스크립트에는 SDK 빌드 단계가 없고, 실행 파일에서 상위 Content를 찾는 경로와 배포 파일 27개의 해시도 일치했다.

- 수확 중 R로 녹화를 마쳐도 수확·미래 목재 전달·대기 예약이 각각 한 번 저장된다. 녹화 종료 뒤 실제 예약 실행과 저장된 루틴 재생에서 목재가 정확히 전달됨을 확인했다.
- 두 골렘의 재고 경쟁, 사용 가능한 잔량, 다른 골렘의 제작 재료 회수 거부, 제작·건설 비용 점유, 전부 옮기기의 시작 시 수량 고정을 확인했다.
- 자동 훈증이 점유된 약초를 소비하지 않으며 해제 후 재개한다. 점유 중 시설 철거는 거부한다. X 취소·수동 이동·골렘 파괴는 원격 재고의 점유도 해제한다.
- 이동 중 재고 점유와 후속 예약을 저장·복원하고 중복 지불이나 남은 잠금 없이 완료했다.
- 일반 투입칸은 호환 품목만 조회하고 단일 품목을 식별한다. 같은 액체가 입력·완성품 양쪽에 있어도 슬롯 꺼내기는 입력칸만 차감하며 잘못된 슬롯 명령을 엔진에서도 거부한다.
- Shift 계획 메뉴는 실제로 진행/예약한 수확·운반·제작을 순서대로 투영한 품목과 수량만 선택할 수 있다. 예약 키는 입력 XML에서 LeftShift/RightShift로 지정한다.
- WindowsSmoke에 숫자↔정수 슬라이더 양방향 연동, 편의 버튼, 줄어드는 실시간 한도, 시설 집중 화면의 클릭 영역, 단일 슬롯 품목의 수량 직행, 우클릭 꺼내기와 상위 이동·정리를 추가했다. 실제 Windows WPF 실행은 이 환경에서 미실행이다.

## 원형 아이콘과 액션별 호버

- 공통 레이아웃에서 8개 실제 선택지, 별도 페이지 이동, 12시 시작 시계방향 위치, 확대된 원 사이의 간격을 검증했다.
- 9ms 시차와 총 283ms 등장, 설명의 상단 우선 배치·가장자리 회피 계산을 검증했다.
- 제작 미리보기가 결과물 이미지 ID·설명·입력 재고만 사용하며 배치 수량에 따라 필요량을 계산하는지 확인했다. 재료 변동, 부족·해금 대기, 목표 수량이 이미 충분한 경우도 확인했다.
- 액션별 description/icon을 객체팩 XML에서 읽고 기존 이미지 ID와 연결함을 확인했다.
- 이 변경 뒤 당시 공유 엔진 검증 140개 확인 항목과 첫 챕터 전체 캠페인을 통과했다. net48와 독립 TeaBreak 모듈도 빌드했다.
- WindowsSmoke에 실제 원형 컨트롤·8개 페이지·WPF 애니메이션 클록·제작 호버·선택 버튼을 제외하는 어둡게 표시·재고 갱신·닫기 시 정리를 추가했다. 실제 Windows GUI에서의 애니메이션 감각과 화면 표시는 이 Linux 환경에서 미실행이다.

## 공통 버블과 투입칸 회귀

- 건네기와 가져오기에서 같은 카테고리·즐겨찾기·단일 품목 압축을 사용하며 아이템 중복 노출이 없다.
- 숫자 필드의 1개·±1·±5·±10·중간·Max 정수 계산, 최솟값·최댓값·큰 정수와 줄어든 한도를 확인했다.
- XML로 연료·약초·액체 세 칸을 구성하고, 다른 품목·과적·같은 칸의 다른 약초는 실제 운반 액션과 공통 Give에서 거부한다.
- 액체나 연료가 없으면 소비하지 않으며, 입력 도착 시 수동 예약 없이 생산한다. 완성품은 투입칸과 분리하고 가져오기에서 조회·이동된다.
- 첫 챕터 전체 캠페인의 샘물·회복·마나 젤리는 재료 조합을 교체하는 실제 전달 명령만으로 자동 생산했다.
- 생산 도중 저장·복원에서 재료·열을 정확히 한 번 소비한다. 완성품 공간이 차면 기다리고 비우면 재개한다.
- 기존 객체에 새 설정이 없어도 XML 기본값을 적용한다. 예전 지불 완료 예약과 잘못된 물건·미설치 모드 재고는 보존한다.
- 즐겨찾기와 시설별 우선 카테고리가 저장·복원된다.
- 네이티브 버블 탐색·수량 필드·마우스 올림 표시는 net48 컴파일과 WindowsSmoke 코드에 연결했지만 Linux에서 실제 WPF 조작은 실행하지 못했다.

## 상태와 실패 회귀

- 칸 내부 연속 이동, 입력 해제 후 위치 유지, 대각선 속도 정규화, 물 타일 충돌, 칸 경계의 소수 위치 저장·복원을 확인했다.
- 조종 대상이 자동으로 바뀌어도 이전 골렘의 수동 입력이 계속 남지 않는다.
- toggle_mode가 현재 골렘만 전투 모드로 바꾸며, Tab/E가 배포 입력 XML에 연결된다. 실제 키 입력은 아래 Windows 검증 범위와 구분한다.
- 구르기는 즉시 두 칸 순간 이동하지 않고 연속 이동하며 무적 시간과 재사용 대기를 적용한다.
- 같은 InteractionChoices 소스로 다른 골렘은 빠른 사용이 없고 건네기·가져오기·조종 전환을 함께 표시함을 확인했다.
- 상호작용 회귀용 독립 월드에서 나무 두 그루 수확 → 바닥에 먼저 생성 → 해당 수확 골렘 자동 습득 → 목재 10개 직접 전달 → 제작 골렘으로 야외 훈증기 건설까지 실행했다. 수량과 조종 대상 유지도 확인했다. 이 독립 테스트의 초기 설정은 아래 전체 캠페인의 무주입 진행과 별개다.
- 진열대는 상점 밖 설치가 거부되고 재료를 쓰지 않으며, 훈증기 철거물은 수동 습득용으로 남는다.
- E 짧게 누르기는 인접 묶음 하나, 길게 누르기는 2칸 범위 묶음을 수집하고 더 먼 물건은 남긴다. 직접 내려놓은 물건은 자동 수집하지 않는다.
- 소유자 자동 습득에서도 적재 한도 초과 수량이 바닥에 보존되며 0개 내려놓기는 거부된다.
- 자유 이동 녹화는 타일 경로를 하나의 의도로 저장하고 재생·복귀가 프레임당 연속 이동으로 한 루프를 완료한다. 대각선 경로도 기록된 방향을 유지한다.

- Exact 운반 부족 시 양쪽 재고 무변경; 미니 골렘은 두 번째 종류를 적재하지 못함.
- 마력 없는 수동 이동 효율 50%; 자동 반복 정지와 마나 젤리 보충 후 같은 반복 재개.
- 없는 액션은 녹화를 삭제하지 않고 기본 Skip 처리.
- 생산 도중 저장·불러오기 후 재료와 연료를 한 번만 차감하고 완성품 생성.
- 작업대의 목표 재고는 제작 골렘 보관함을 기준으로 계산.
- 겹치는 타일 건설은 재료를 차감하지 않음.
- 마지막 골렘 파괴 시 핵 즉시 회수·물건 드롭·엔린의 재조립, 반복 틱에서 핵 중복 없음.
- 후퇴 시 보스·돌 주먹·호수 물 타일 초기화. 처치 후 저장·재로드해도 보스와 보상 재생성 없음.
- 미설치 모드의 객체·물건·JSON 필드, 초과 적재, 전체 타일 상태를 저장 후 복원.
- AND/NOT 조건, 한 자식 메뉴 접기, 같은 이름의 액션 하위 라벨, 접지 않는 폴더를 확인.
- 팩 경로가 자신의 디렉터리를 벗어나지 못함.

## Windows 앱에 연결되는 세션

WPF와 같은 DesktopSession 소스를 net10.0 테스트에 포함해 실행했다.

- 대사 중 명령 차단과 시간 정지.
- 세션에서 외부 DLL로 직접 명령 전달, 연속 이동과 타일 판정 완료.
- 일시정지·창 비활성 상태에서 시간과 명령 차단.
- 저장 시 이전 파일의 원자적 .bak 보존과 위치·경제 상태 복원.
- 기존 세이브에 TilesetId가 없으면 원래 타일셋으로 복원.
- 타일 통행 여부를 tileset 정의에서 조회.
- 독립 타일 팩이 타일 하나만 바꾸고 다른 정의는 보존.
- 독립 그림 팩이 애니메이션 하나와 오프셋을 바꾸고 다른 상태는 보존.

이는 세션 로직 검사이며 네이티브 마우스·키보드 조작이나 실제 창 렌더링을 대신하지 않는다.

## 독립 모듈

기본 솔루션 밖의 examples/TeaBreak를 net48과 net10.0으로 별도 빌드했다. net10.0에서는 새 DLL, 번역 XML, 건설 정의를 넣고 다시 쿠킹해 찻상 건설과 커스텀 회복 액션을 실행했다. Host나 기존 모듈에 프로젝트 참조를 추가하지 않았다.

## 실제 이미지와 시트

- 배포 이미지: 정적 SVG 67개, 캐릭터별 투명 RGBA PNG 12장. XML에서 사용 중인 파일 경로 77개가 모두 존재한다. 두 정적 지형 SVG는 여분이다.
- 대기·이동·작업·공격·피격·쓰러짐 6상태 × 12종 = 72개 애니메이션, 상태별 4프레임으로 총 288프레임이다.
- 모든 프레임이 이미지 경계 안에 있고 비어 있지 않으며, 각 애니메이션이 서로 다른 네 그림을 참조한다.
- 실제 XML 영역·pivot으로 만든 모아보기에서 포즈·투명도·잘림을 시각 확인했다. 정적 캐릭터를 흔들어 만든 애니메이션은 아니다.
- 엔린의 팔찌, 머리 위 미니골렘과 칠판이 포함돼 있다.
- 게임은 외부 SVG/PNG를 로드한다. WPF의 SVG 해석과 게임 화면에서의 크기·입력 감각은 Windows에서 추가 확인이 필요하다.

## 재현

- Windows: 로컬 Content의 이미지가 준비된 저장소에서 Verify.bat. 포함된 net48 검증 프로그램과 WPF --smoke가 실행되며 TestResults/windows에 결과와 창 캡처를 남긴다. 소스 변경 후에는 Build.bat을 먼저 실행한다. 스모크 검증은 별도 테스트 세이브와 소량의 전달·줍기 테스트 재고를 사용한다. 실제 WPF 건네기·가져오기 버블 → 품목 → 수량, 즐겨찾기·상위 메뉴, 잘못된 수량 거부와 5개 편의 버튼·슬라이더, 시설 집중/투입칸 좌우클릭, Tab/Space 키 핸들러, E 세션 처리, 자유 이동과 저장, 모든 메뉴를 확인하도록 구성했다. 이 환경에서는 해당 스모크를 실행하지 못했다.
- Linux/macOS: bash verify.sh. WPF를 제외한 같은 공유 로직을 net10.0으로 검증한다.
- 이미지: python tools/verify-art.py. 결과는 TestResults/art에 기록한다.
- 확장팩: examples/TeaBreak/README.md의 명령을 사용한다.

장시간 플레이·부하, 다양한 Windows DPI·그래픽 드라이버, 제3자 팩 조합은 검증하지 않았다.


## 고정 버블 위치와 표시 정보

- 1~8개 메뉴가 동일한 95px·45도 간격의 자리들을 채우는지, 페이지 전환에서도 첫 자리가 12시로 유지되는지 확인한다.
- 단순 버튼의 상세 설명 기본 비활성, 명시적 제작 미리보기와 XML `details` 덮어쓰기, 표시 컨텍스트의 누락값 처리, 단가/수량 합계 표시를 공유 코드 검증에 포함한다.
- 독립 TeaBreak DLL과 번역 XML에 버블 이름·배지·호버 정책을 넣어 기존 엔진/모듈 프로젝트 참조 없이 적재되는지 검증한다.
- Windows `--smoke`는 외곽선 이름의 지속 표시, 뒤로가기/일반 버튼의 설명창 없음, 고정 8자리/마지막 페이지 위치, 상품·구매 버튼 가격과 숫자/슬라이더 합계 갱신을 검사하도록 확장했다. Linux 환경에서는 WPF 스모크를 컴파일만 했으며 실제 실행은 Windows에서 `Verify.bat`로 확인해야 한다.


## 묶음 생략·빈 메뉴·빠른 사용 회귀 검사

- 다중 자식을 가진 단독 묶음과 연속된 단독 층 제거, 형제 메뉴가 있는 묶음 유지, 단일 실행 버튼의 자동 실행 방지.
- 빈 묶음의 비활성 유지, 동적 내용 추가/제거에 따른 재활성화, 비활성 부모 조건 우회 방지.
- 지정된 빠른 사용이 비활성일 때 다른 행동을 선택하지 않음. 수확 가능 상태를 검사해도 작업·예약·재고를 변경하지 않고 Shift 예약은 유지됨.
- Windows 스모크에는 실제 상인 좌/우클릭의 동일한 펼침과 뒤로가기, 주문 없는 게시판의 비활성/우클릭 대체, 주문 추가/제거, 마지막 내용 제거 후 상위 복귀, 열매 없는 나무의 수확 대신 벌목을 자동 실행하지 않는 경로를 포함했다. 이 환경에서는 WPF 실행이 불가능하므로 해당 검사는 컴파일까지 확인했다.


## RTS 입력·게임 HUD·예약 재고 (2026-09-29)

225개 PASS 항목과 전체 캠페인(868.6초, 12개 퀘스트, 동굴 입구), 독립 TeaBreak DLL, net48 전체 빌드 및 77개 외부 이미지 참조 검증을 통과했다.

## 데굴돌 누락 정정 (2026-09-29)
