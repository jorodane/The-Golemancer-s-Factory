# 검증 기록 — 첫 챕터

2026-09-28, .NET SDK 10.0.401 / Linux / Chromium에서 검증했다.

## 빌드와 실제 캠페인

- Release 빌드: 경고 0, 오류 0. 외부 NuGet 패키지 없이 전체 솔루션 빌드.
- 10개 객체팩, 12개 구현 DLL, 29개 액션 구현, 7개 런타임 시스템을 로드.
- 모든 액션 구현이 기본 AssemblyLoadContext 밖의 외부 DLL에서 로드됨을 확인.
- 새 게임부터 자원 주입이나 퀘스트 강제 완료 없이 실제 액션 명령으로 12개 퀘스트 완료.
- 판매 → 핵 구매·조립 → 건설·장비 → 사냥·훈증 생산 → 상점·복합 주문 → 샘물의 왕 → 채광·마나탑 → 자동 순환 → 미니 운반 → 동굴 입구 순서.
- 검증 실행의 게임 시간 885.5초, 일반 판매 16회, 자동 루틴 완주 1회. 명령 대기 시간을 압축해 실행하는 테스트의 수치이며 일반 사용자의 플레이 시간 추정은 아니다.
- 보스 처치에 따른 호수 타일 변경, 동굴과 공방의 골렘 간 조종 전환, 동굴에서 공방으로 복귀 확인.

## 상태와 실패 회귀

- Exact 운반 부족 시 양쪽 재고 무변경; 미니 골렘은 두 번째 종류를 적재하지 못함.
- 마력 없는 수동 이동 효율 50%; 자동 반복 정지와 마나 젤리 보충 후 같은 반복 재개.
- 없는 액션은 녹화를 삭제하지 않고 기본 Skip 처리.
- 생산 도중 저장·불러오기 후 재료와 연료를 한 번만 차감하고 완성품 생성.
- 작업대의 목표 재고는 제작 골렘 보관함을 기준으로 계산.
- 겹치는 타일 건설은 재료를 차감하지 않음.
- 마지막 골렘 파괴 시 핵 즉시 회수·물건 드롭·엔린의 재조립, 반복 틱에서 핵 중복 없음.
- 후퇴 시 보스·돌 주먹·호수 물 타일 초기화. 처치 후 저장·재로드해도 보스와 보상 재생성 없음.
- 미설치 모드의 객체·물건·JSON 필드, 초과 적재, 전체 타일 상태를 저장 후 복원.
- AND/NOT 조건, 한 자식 메뉴 접기, 같은 이름의 액션 하위 라벨, 접지 않는 폴더를 확인.
- 팩 경로가 자신의 디렉터리를 벗어나지 못함.

## 독립 모듈 실험

`examples/TeaBreak`를 기본 솔루션 밖에서 별도 빌드했다. 새 DLL, 번역 XML, 건설 정의를 넣고 다시 쿠킹해 찻상 건설과 커스텀 회복 액션을 실행했다. Host나 기존 모듈에 프로젝트 참조를 추가하지 않았다.

## 화면과 이미지

- 타이틀, 엔린 대사창, 키보드 이동, 건설 메뉴, 녹화와 기록 보관함, 일시정지, 직접 저장·불러오기를 브라우저에서 조작.
- 마우스로 널린초를 수확하고, 수량 3을 입력해 진열대로 Exact 운반한 뒤 손님의 구매까지 확인.
- 1280×800, 1440×900, 1920×1080 화면 확인. 브라우저 예외 없음.
- SVG 67개와 투명 PNG 미리보기 67개, 모아보기 그림, 분류별 경로 매니페스트 생성.
- 별도 Assets 폴더를 설치한 상태로 화면 조작 검증. 엔린의 팔찌·머리 위 미니골렘·감정 칠판을 시각 확인.

빌드와 캠페인은 `Verify.bat` 또는 `bash verify.sh`, UI는 `tools/browser-smoke.mjs`로 재현할 수 있다. 독립 팩은 먼저 예제 프로젝트를 빌드한 뒤 검증 프로그램에 `--example`을 전달한다. Windows/macOS 네이티브 환경, 모바일, 장시간 부하와 다수의 제3자 팩 조합은 이번 검증에 포함하지 않았다.
