# Shared workspace navigation and project entry

This continuation applies the final UI/context contract to the current migration.
The installed CoreTools factory owns identical header/toolbar/menu definitions and
actions. Native adapters position those elements and supply captured-project IO,
window/surface opening and execution boundaries. Mounting reads state only.

The header places `≡` beside the selected project name. Its common menu contains
project information, project settings, project folder and project exit. Internal
navigation uses `▦`, beside the mailbox and Run/Stop controls. Internal choices
preserve existing objects, functions, packs, execution settings and project tools;
this adds no new authoring features. The installed model owns menu selection,
notice/failure state, busy/current-session guards and explicit Run/Stop choice.

Selected-project entry requests Run once through the installed model after the
selected session is attached. Reopening menus or remounting views never replays
Run. Failed entry remains reviewable and can be explicitly retried; no failure
claims a running project. The execution adapter retains existing project-target,
process, build and OS presentation boundaries. No provider or credential operation
occurs through this navigation contract. Document drafts remain local and incoming
changes keep existing clash callbacks; navigation introduces no locking system.

The same installed public conversation component forms the wide lower panel on
Windows, Android and Linux. Transcript scrolling excludes its composer; chat/log
selection and latest meaningful log are shared. Private Helper overlays, temporary
Yogi and original read-only recovery remain separate from public capture.

Acceptance: all three portable renderers verify installed ownership, inert mount,
project/internal menu separation, exact action IDs, current-session revocation,
busy guards, one-shot explicit entry, Run/Stop, execution failure/retry, menu
cancel/reentry and project exit. Native Windows/SDL checks exercise placement and
injected execution boundaries. Android source/APK checks remain distinct from
physical-device execution. Existing startup motion, saved-Agent skip, global
Helper memory, consent and conversation flows must continue to pass.
