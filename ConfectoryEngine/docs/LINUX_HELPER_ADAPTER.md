# Linux production Helper and temporary Yogi adapters

This adoption mounts the installed definitions/actions described by
GLOBAL_HELPER_CHAT.md, HELPER_SUPERVISION.md, TEMPORARY_YOGI.md and
SHARED_REVIEW_CHOICE.md. It does not establish complete Linux shell parity.

Application-owned global execution/timelines survive closing individual views and
explicit project switches. A genuine null session is supported. Opening a Helper
or attaching a parcel cannot open a project, join a participant, create a Worker,
connect a provider or send a request. Explicit project selection binds only that
validated session, its held workspace-role service and its installed execution.
The next session and roles are validated before detaching the prior binding.
Captured requests/reloads/reviews cannot mutate a later project. Exiting detaches
project execution, cancels its pending work and clears only temporary Yogi state.

Each floating conversation uses a separate native renderer with the exact installed
common view. The native adapter measures declared dimensions, applies the installed
timeline's fit/placement result and inverse-transforms input. Views can receive
input while another request is connecting or reviewing. Closing preserves draft and
work; cancellation remains request-specific. Ctrl+Enter sends the focused composer;
text copy and scrolling use existing native input. Only displayed/focused turns
receive receipts. Dragging a character commits the shared placement. Private
Helper overlays never enter automatic project screenshots or semantic picking.

Global transport/storage stays in its private Helper scope with no project tools.
Project host boundaries supply captured consent/options, native dispatch, explicit
pack sources, existing project runner, image capture and review services. The
installed pack owns request authority, memory/locality, tools, Worker reservation,
reviewed application and late cancellation. Tests inject provider/credentials and
history; no paid requests, authentication or credential writes occur.

Selective review uses the published common choice. Existing collaboration review
coordination and incoming-change callbacks remain the reconciliation mechanism;
unconfirmed drafts stay local. Overlapping proposals mount a pack-owned conflict
choice with exact candidate identity, readable comparison, permission revalidation,
cancel/retry and stale-choice recomparison. No object lock or new supervisor
persistence system is introduced. Native async boundaries preserve UI dispatch
through delayed conflict choices and proposal cleanup.

Temporary Yogi uses the same application draft and inspector as Windows/Android.
Native capture/navigation/image display and drag/drop are service/input boundaries.
Capture excludes private layers. New items unseal the same identity; parcel drops
validate and copy before attaching or delivering. Whole close/Esc and project exit
clear the current draft, retaining delivered and legacy bytes. Foreign/deleted EY
navigation fails visibly without opening another project.

Acceptance covers actual SDL startup/home sidebar entry, global send, failure and
retry, close/reentry during delayed connection, request-specific cancel and late
provider disposal; explicit project binding, source/consent revocation, incoming
clashes and selective review without premature writes; detach/switch locality and
late reload; native placement/keyboard/receipt behavior, private capture exclusion,
Yogi item/seal/unseal/new-item/drop/inspection/exit lifecycle. Unsupported legacy
Worker execution remains separately disabled until readable recovery/replacement
is verified; enabling local Helper entry cannot claim that capability.
