## 화면 순서

1. **시작:** 완전히 빈 배경에서 중앙의 Confectory 로고 → 이름 → `AI-Integrated Development Environment` → **AI Agent 연결** → **나중에**가 순서대로 나타난다. 이름과 로고는 아주 조금 떠오르며 감속하고 나머지는 페이드인한다. 콘솔·상태줄·프로젝트·메뉴·AI 목록·안내 문구는 시작 화면에 노출하지 않는다. 연결이나 건너뛰기 이후에는 프로젝트 메인 페이지로 이동하며 모델 요청이나 저장된 작업을 자동 실행하지 않는다.
2. **프로젝트 선택:** 왼쪽 112px AI 관리에 Agent와 Helper의 원형 아이콘을 두 개씩 배치한다. 각 구획 마지막은 점선 원의 +이며 프로필은 오른쪽의 같은 위치에서 내용만 바뀐다. 가운데는 프로젝트 제목과 2열 카드만 표시한다. 첫 슬롯은 점선 테두리의 새 프로젝트, 기존 프로젝트는 마지막으로 연 시간 순서다. 상단 메뉴·팩 가져오기·콘솔·상태줄·도움말은 이 화면에서 숨긴다. 이름 클릭/F2로 카드 안에서 이름을 바꾸고, ⋮에서 아이콘·실제 폴더·확인 후 삭제를 사용한다. 삭제는 같은 저장 장치의 `.ConfectoryTrash`로 폴더를 옮기므로 복구할 수 있다.
3. **프로젝트 안:** 왼쪽 AI 관리와 하단 프로젝트 채팅, 중앙 작업 공간, 오른쪽 아래 **▶/■ 실행**과 **≡ 탐색**을 유지한다. 새 프로젝트는 Main Pack과 비어 있는 메인 화면으로 시작한다. ≡에서 카테고리·개념·객체, 기능, 팩을 탐색한다. 전체 프로젝트 채팅·개인 기록·관리 도구는 필요할 때 별도 창으로 연다. 목록으로 돌아갈 때 실행 중인 작업은 먼저 마치거나 취소한다. 개념 편집 규칙은 [프로젝트 작업 공간](PROJECT_SPACE.md)을 참고한다.

기준은 복잡한 편집 도구보다 전략 시뮬레이션의 작업 공간에 가깝게 느끼는 것이다. 탐색기·고정 문맥 패널·작업자 탭을 기본 화면에서 분리했다. 항목의 이름과 설명은 직접 클릭해 편집하고, **▾ 자세히**는 선택과 별개로 그 항목 내부만 펼친다. XML은 도구에서 명시적으로 연다. 변경 확정은 기존 버전·소유권·검토 절차를 사용한다.

프로젝트에 참여한 도우미는 사이드바에 이름·작업 상태·새 답변 점으로 표시한다. 그 외 작업자는 참여자 도구에서 열 수 있다. Windows는 아이콘 더블클릭 또는 메뉴의 **대화창 열기**, Android는 아이콘 탭으로 독립 대화를 연다. 여러 대화의 요청 입력을 동시에 열어둘 수 있으며 하나를 선택하거나 닫아도 다른 대화나 진행 중인 작업을 닫거나 취소하지 않는다. 대화창은 개념 편집 페이지 위에서도 이동할 수 있다. 드래그 위치와 표시 여부는 보는 사람별로 저장하며 화면 크기에 맞춰 보이는 공간 안으로 조정한다. 숨긴 작업자의 새 답변은 최대 네 개의 미리보기 알림으로 표시한다. 읽음 처리는 실제로 연 답변 ID만 대상으로 하며 이후 도착한 답변은 남겨둔다. 전체 대화는 **기록** 창에서 확인한다. 다른 사람의 작업자는 공개 답변 확인과 프로젝트 채팅 호출만 가능하다.

새 프로젝트는 `EditorPacks/project.workspace`에 XML 메인 화면을 가진다. Golemancer는 `EditorPacks/golemancer.workspace`에서 공방 제목·안내·아이템 시작 분류·카드 배치를 정의한다. 기존 코어 DLL을 상속하는 XML 전용 메인 화면만 자동 적용하고, 새 DLL·빌드 소스·추가 의존 팩을 가진 프로젝트 팩은 명시적 적용을 유지한다.

내장 웹 AI, ChatGPT 플러그인↔에디터 연결, 웹 대화 첨부 스크립트, 터널 설치와 MCP 실행 프로젝트를 제거했다. 기존 설정·대화 파일을 지우지는 않는다. 일부 과거 데이터 형식은 기록 호환성과 내부 Yogi 스냅샷에 사용한다. Windows 배포 스크립트는 이전 빌드에 남은 WebView2와 MCP 실행 파일도 제거한다. Codex의 계정 로그인은 내부 작업 AI 인증으로 유지한다.

## 프로젝트 생성과 역할

중앙 생성창은 프로젝트 아이콘 → 이름 → 메인 에이전트 → 도우미 → **AI에게 프로젝트 설명** → 저장 위치 → 취소/만들기 순서다. 이름만 필수다. 유형·템플릿 선택은 없으며 이름으로 안전한 기본 폴더를 만든다. Windows 기본 저장 위치는 `~/Confectory/Projects`, Android는 앱이 접근할 수 있는 기기/외부 저장소의 Confectory/Projects다. Android의 명시적인 탐색기 동작은 실제 앱 폴더를 읽는 기본 폴더 탐색창을 연다.

Agent·Helper 선택도 사이드바와 같은 원형 아이콘을 사용한다. Helper 중 한 명에 붉은 테두리와 MAIN 라벨을 붙이며 첫 선택이 기본 MAIN이다. 우클릭(Android 길게 누르기)으로 역할을 이동하거나 연결을 해제한다. 도우미가 없으면 MAIN도 없다. 메인 에이전트는 Helper의 연결 원본과 독립적이다. 없거나 해제된 경우 프로젝트는 만들 수 있지만 Worker 생성은 사용할 수 없다고 알려준다. 프로젝트 안의 Agent 원을 눌러 이후에 변경할 수 있다.

프로젝트의 Studio 요소는 설명·대표 아이콘의 프로젝트 상대 경로·메인 Agent ID·순서 있는 Helper ID·Main Helper ID를 저장한다. 인증 정보와 개인 기억은 포함하지 않는다. 마지막으로 연 시간은 기기 설정에 저장하며 새 목록을 그릴 때 갱신하지 않는다. 설명은 각 AI 요청 시점에 별도 초기 문맥으로 고정해 실제 API/Codex 요청에 포함한다. 생성 후 즉시 같은 빈 작업 공간을 연다. 별도의 첫 요청창이나 자동으로 열린 Helper 대화는 없으며 사이드바의 아이콘이나 참여자 도구로 대화를 연다. 첫 요청을 보내기 전에는 모델 작업을 자동 실행하지 않는다. 기존 Studio 정보가 없는 프로젝트는 기존의 로컬 Helper 참여를 표시하고, 명시적으로 저장한 빈 목록에는 다시 추가하지 않는다.

## AI의 세 역할과 총집행자

확정된 상세 계약과 구현 순서는 [HELPER_SUPERVISION.md](HELPER_SUPERVISION.md)를 따른다. 아래는 기존 승격·Worker 직접 채팅 설계를 대체하는 목표 동작이며, 구현 완료를 뜻하지 않는다.

| 역할 | 범위 | 유지하는 정보 |
|---|---|---|
| Agent · 에이전트 | 이 기기의 연결 원본 | 제공자·모델·암호화된 인증 슬롯·활성 상태 |
| Worker · 작업자 | Helper가 감독하는 내부 실행 단위 | 독립적인 Task·Callback·도구 범위·취소·검토·체크포인트 |
| Helper · 도우미 | 사용자와 대화하는 정체성이자 작업반장 | 이름·이미지·전문성·초기 징집 설정·경험·명시적 장기기억 |
| Main Helper · 총집행자 | 일반 Helper 권한에 총집행자 권한 추가 | 전체 지시·동적 Helper 징집·총집행자 일지·총집행자 전용 증강 권한 |

사용자는 Helper에게 요청한다. Worker별 직접 채팅과 Worker→Helper 승격 진입점은 검증된 대체 경로가 준비될 때 제거한다. 기존 승격으로 만들어진 Helper의 정체성·최초 경험, Worker 기록, 장기기억은 삭제하지 않고 복구 가능하게 보존한다. 각 Helper는 자기 Worker를 감독하고, Main Helper도 미배정·교차 작업 등 필요한 일을 위해 Worker를 직접 징집할 수 있다. 팀은 고정하지 않으며 적합한 전문 Helper가 없으면 징집한다. Main Helper가 총집행자 권한으로 전반적인 지시를 내릴 때는 총집행자 일지를 기록한다. 증강은 총집행자 권한에만 속한다.

Helper 프로필 아래에는 Worker 수와 상태 점을 표시하고, hover/focus에서는 작업 상태를 짧게 보여준다. Worker의 편집 대상에는 감독 Helper의 아이콘을 표시하되 배치나 아이콘으로 제어 권한을 추론하지 않는다. Task·Callback은 채팅 세션과 별도 정체성을 유지한다. 미확정 편집은 로컬에 두고 외부 변경은 기존 충돌 콜백으로 처리하며 서로 막는 편집 잠금을 추가하지 않는다.

Helper의 전문성·성격·역할·관련 초기 설정은 징집 시 보존한다. 작업반장이 사라지고 총집행자가 남아 있으면 기존 Task와 살아 있는 Worker를 먼저 확인한 뒤 유사한 특성의 임시 작업반장을 만들 수 있다. 단순 미응답을 고장으로 단정하지 않는다. 명시적 권한 인계와 revision/epoch 검증으로 복귀한 원래 Helper의 중복 지시를 막는다. 이 복구 기능은 감독 상태 영속화 단계에서 구현하며 사이드바 렌더러에 넣지 않는다.

Helper의 명시적 공통 기억은 프로젝트를 넘어 간결하고 중요한 맥락을 유지하고, 개별 요청 문맥은 의미적으로 필요한 범위에 한정한다. 공개 프로젝트/Room 대화와 공개 제안은 함께 보되 개인 기록·API 키·Helper 기억은 자동 공유하지 않는다. 프로필의 이름·이미지·경험·기억 관리 및 성격/관계 표현 설정은 유지한다.

## 신문고

사건 또는 개선 제안에는 보고자·담당자·대상·치명도·근거·요청·처리 상태와 변경 묶음을 기록한다. AI는 `confectory_incident` 도구로 보고·재분류·변경안 첨부·처리 결과를 남긴다. 판단이 불가능하면 `needs-user`로 남겨 사용자가 개입한다.

현재 세션에서 새로 생긴 담당 사건은 작업 종료 후 처리하며, **Urgent**이면 진행 요청을 취소하고 초안·실행 기록·원래 목표를 체크포인트로 보존한다. 사건 해결 후 현재 파일과 인계 초안을 확인하는 새 요청으로 재개한다. 이미 적용한 작업이나 중단된 모델 요청을 그대로 재실행하지 않는다. 재시작 후에는 신문고의 **중단 작업 재개**를 명시적으로 선택한다. 제공자가 취소에 응답하지 않으면 기다림을 종료하고 사용자 판단으로 전환한다.

제안은 해당 변경 묶음과 지문을 묶어 검토한다. **사용자가 미리 부여한 경로 범위**를 모두 포함하는 다른 AI가 승인·수정 요청·반려할 수 있다. 작성자의 자기 승인은 금지한다. 치명도는 권한을 올리지 않는다. 검증 실패·변경안 수정·권한 철회는 기존 승인을 무효화한다. 범위 승인은 파일 변경 검토에만 사용하며 빌드·실행 같은 후속 작업은 공통 검토창에서 선택한다. 승인 자체와 실제 파일 적용 결과는 별도로 기록한다.

## 충돌·격돌

Windows와 Android에서 모든 후보가 이 기기에서 제어 가능한 AI인 경우 같은 공개 증거를 주고 실제 제공자 호출로 라운드를 진행한다. 각 AI는 최대 10회 발언한다. 초기 HP는 100이며 호스트가 확인한 구문·검증 실패, 계약·사용자 조건 위반만 감점 근거가 된다. 동일 증거는 중복 감점하지 않는다. 모델의 주장만으로 점수를 바꾸거나 검증 성공을 만들어 내지 않는다.

합의하면 조기 종료하고, 결정권자가 한 명 남거나 10턴이 끝나면 유효 후보 중 HP가 높은 쪽을 선택한다. 동점은 최초 제출 순서다. 사람이 발언하는 순간 자동 결정을 멈춘다. 실패한 모델 호출·유효 후보 없음·원격 소유 후보는 사용자 판단으로 돌린다. 협의 결과는 최종 검토를 위한 Resolution ChangeSet이며 곧바로 파일을 덮어쓰지 않는다.

수용한 Resolution을 그대로 반복하는 후손 변경은 여러 세대의 부모를 추적해 중복 알림을 막는다. 새로운 실제 변경·충돌은 계보와 상관없이 계속 전달한다. Scope 인계는 기존 TAKEOVER/YIELD의 명시적 제안·수락을 유지한다.

## Windows·Android 프로젝트 연결

프로젝트에서 **함께 편집 · 연결**로 호스트를 열고 초대 코드를 만든다. 같은 프로젝트 ID를 가진 Windows 또는 Android 기기가 그 코드로 참여한다. Android는 PC 연결 창의 **모바일용 프로젝트 문서 ZIP 내보내기**로 만든 ZIP을 프로젝트 목록에서 가져온 뒤 연결한다. 이 ZIP에는 프로젝트에 선언된 확정 문서만 포함하며, DLL·이미지·API 키·개인 대화·도우미 기억은 포함하지 않는다. Android에서도 호스트를 열 수 있다. 양쪽에서 호스트 주소에 접근할 수 있어야 하며 터널·포트포워딩·자동 탐색은 제공하지 않는다. TLS 1.2, 초대 코드의 인증서 지문과 무작위 토큰으로 연결한다. 초대는 연결 권한이므로 공유할 사람에게만 전달한다.

참여자·위치·공개 채팅과 열어 본 편집 가능 문서의 작업본을 동기화한다. 문자 단위 동시 입력은 구문이 불완전해도 전달하고, 서로 다른 구간은 합친다. 전송 중의 추가 입력은 수신 확인 후 이어 합친다. 겹치는 변경은 양쪽 내용을 표시하고 사용자가 선택하며 로컬 초안을 보존한다. 개인 로그·기억·인증 정보·바이너리는 전송하지 않는다.

클라이언트의 확정 요청은 호스트의 검토창으로 보낸다. 호스트가 실제 확정한 버전은 다른 기기에서도 로컬 적용 검토를 거친다. Android 참여자의 AI 변경은 먼저 공동 작업본 초안으로 넘기며 파일 확정은 호스트에게 요청한다. 연결만으로 원격 파일을 자동 덮어쓰지 않는다. 연결은 최대 8명, 메시지는 최대 2 MiB이며 연결 종료·재시작 후 자동 재접속하지 않는다.

## 플랫폼과 검증 범위

| 기능 | Windows | Android |
|---|---|---|
| 시작 인트로 · 이후 콘솔·AI 관리·프로젝트 채팅 | 구현 | 구현 |
| 독립 작업자·도우미·기억·신문고 | 구현 | 구현 |
| 제공자 | Codex / Anthropic API / OpenAI API / 외부 DLL | Anthropic API / OpenAI API |
| 사용자 검토·AI 범위 승인·긴급 체크포인트 | 구현 | 구현 |
| 도우미 이미지 편집·실제 AI 충돌 라운드 UI | 구현 | 구현 |
| 원격 프로젝트 문서 동기화 UI | 구현 | 문서 ZIP 가져오기·호스트/참여·문서/채팅·검토 구현 |
| 팩 컴파일 | 로컬 .NET SDK | Windows에서 빌드한 ZIP 가져오기 |

검증은 Windows net48 솔루션 컴파일, Android 전체 빌드, 새 Studio 검증 프로그램, 기존 resident/editor-pack 회귀 검사와 고정 SDK를 사용한 전체 게임 캠페인을 구분한다. Windows 자동 검증은 실제 WPF 창에서 프로젝트 메인 팩을 로드하고, 작업자 클릭·이동과 카드 F2·인라인 입력·입력 상태 복원을 네이티브 이벤트로 확인한다. 사람의 전체 사용 동선·실제 IME 입력·Android 실기기 조작은 별도 확인 범위다. 통신 검사는 실제 로컬 TLS 소켓을 사용한다. 제공자 프로토콜 fixture는 유료 모델 응답을 검증한 것으로 표현하지 않는다.

Android 보강 검증에는 문서 ZIP 왕복·비공개 파일 제외·잘못된 ZIP 거부·재시작 초안 복원·명령 실행 차단·실제 변경안 충돌 조정과 검토 중 원본 변경 재비교를 포함한다. 빌드·자동검증 성공은 실제 기기 간 네트워크나 유료 모델 응답 검증을 뜻하지 않는다.

핵심 검증: `python tools/verify-studio.py --dotnet <dotnet 경로> --network`.
