# Repository layout

- The game workspace is Golemancer/. Read Golemancer/AGENTS.md for gameplay and platform requirements. Keep game modules, XML/art, native game clients, tests, docs and ready-to-run builds together there.
- src/PackEngine.Contracts and src/PackEngine.Runtime are game-independent engine sources. Engine.slnx builds only those projects; they must never reference a game assembly, model, rule, content key or source path.
- All domain contracts, simulation, movement, recordings, inventory, economy, terrain integration and game-specific XML parsing belong in Golemancer/src/Golemancer.Contracts or Golemancer/src/Golemancer.Runtime. Other game modules depend on the game contracts, not concrete modules.
- Game projects use only the PackEngine binaries in Golemancer/SDK. Engine upgrades are explicit work: tools/export-sdk.py establishes a new source-hash baseline; game-only work must preserve that SDK and its lock.
- editor/ contains the generic Project Studio workspace, CLI, WPF shell and explicit assistant providers (docs/EDITOR.md). Keep project/game semantics in the consumer's .packproject and index rules. Opening a project must not execute its commands or DLLs. Preserve separate user-open, exported-context and provider-read records; never fabricate model replies or runtime-resolved relationships.
- Resident editor conversations use explicit single/range pointing frozen at send time. Ordinary chat must not attach hover or selection content. Resolve XML relations and read implementation slices on demand; edits/builds must honor each request's pack scope and observed versions. Keep real Codex traffic distinct from protocol fixtures (docs/RESIDENT_AGENT.md).
- Connection setup belongs in an editor-owned wizard: collect necessary information, show scope and installation consent, then execute supported setup and checks with progress, cancellation and retry. Do not make users edit MCP/JSON configuration files for the normal setup flow. Distinguish local diagnostics from a successful external tool call, and hand off account approvals or app-only steps explicitly.
- Confectory now uses internal Agent–Worker–Helper identities only (docs/INTERNAL_AI_STUDIO.md). Do not restore embedded web AI, ChatGPT plugin linking, tunnels, or the retired MCP executable. Codex account authentication is still supported.
- The default project frame is the same for new and existing projects: a narrow circular Agent/Helper sidebar, public project chat below it, a project-owned central work surface and fixed bottom-right run/stop and navigation buttons. New projects start with an empty MainScreen and Main Pack. Open concept/Variation/schema, object fallback tables, custom Views, functions and Pack management explicitly without shifting this frame. Keep classification, inheritance, references, schema, data, View, stable identity, Source Pack and logical Namespace separate (docs/PROJECT_SPACE.md). Worker detail opens by selection; XML, inspectors, full transcripts and management tools stay behind explicit actions.
- Startup begins on a blank background and reveals only the centered Confectory logo, name, one-line AIDE subtitle, primary Agent connection action and quiet Later text action. Keep the editor shell, console and status hidden until onboarding completes; connecting or choosing Later opens the two-column project home with a narrow two-avatar-wide Agent/Helper sidebar. Keep menus, console, status and other editor controls hidden on this home. Project creation requires only a name; preserve the Agent → Helper → initial explanation order and circular identities. Save project-specific Main Agent and ordered Helpers independently, display the red MAIN role on one existing Helper, and freeze the initial explanation into AI requests. Recent projects sort by last-open time; deletions require confirmation and move only the selected project folder into recoverable storage. Project chat and project participants appear only after entry. Do not auto-start saved model requests or open pack windows during onboarding.
- Helpers own private history and project-scoped memory. Public mentions and AI proposal reviews use fresh provider contexts containing only the shared evidence. Urgent incidents may suspend work but never grant approval rights. Preserve checkpoints, hashes, review scopes, and explicit human decisions.
- Runtime DLL loading is required. Content modules must not depend on one another's concrete types.
- The engine remains pack-based; deployment bundles the selected engine packs with the platform host. Project execution composes immutable deployed engine packs with project overlays in separate sessions (docs/PROJECT_EXECUTION.md). Never let project authoring rewrite deployment files or substitute host/runtime assemblies. Keep projectpack import staging separate from explicit execution consent.
- Engine UI implementations belong in independent packs (see docs/UI_PACKS.md). Core contracts/runtime must not reference default widget modules. Distribute those DLLs separately from the frozen core SDK.
- Pack and definition inheritance follows docs/INHERITANCE.md: one parent, omission inherits, explicit values override, additions preserve contracts, no removal. Keep game-specific merge semantics out of the generic resolver and retain inspectable setting origins.
- Host/frame callbacks use the engine timing scheduler. Read docs/TIMING.md before changing ordering or ownership; preserve stable priorities, immediate unregistration and per-session attachment.
- Camera state, interpolation and projection belong to the engine rendering API (docs/CAMERA.md). Consumers supply game policies and native drawing; use the last-drawn immutable view for picking and keep camera changes independent from terrain cache invalidation.
- Never commit or upload generated builds (EXE, DLL, APK, runtime packages) or image bytes through assistant Git tools. Commit source and build scripts only; the user pulls and runs BuildEditor.bat locally. Existing image blobs may be relocated by reusing their Git SHAs. Do not change .gitignore. Stage explicit source/runtime paths, never an entire worktree containing generated files.
- Preserve local images and saves when changing paths. Root Start.bat delegates to the game and copies only missing legacy files without deleting originals.
- Verify meaningful modules and the full campaign before pushing. Existing user authorization for commits and pushes applies.
